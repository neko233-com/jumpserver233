# SSH 执行工作区

> 中文 | [English](./SSH-WORKSPACES.en.md)

资产编辑中的可选 `ssh_workspace` 为 Web SSH、`jms ssh`、`jms exec`、普通 SSH 作业和 Web SFTP 指定远端文件范围。它限制目录树的实际访问，适用于受限操作员或 Agent。默认留空使用普通 SSH。竞品仍为 JumpServer 企业版，本功能不代表完整目录命令规则已经完成。

## 配置与使用

管理员先在 Linux 主机建立目录并配置远端账号的普通文件权限，再在“资产 → 编辑 → SSH 执行工作区”填写绝对路径，例如 `/srv/workspace`。目录必须已存在，所有路径组件均不能是符号链接；不自动创建目录或提升权限。系统、内核接口和运行库目录不能作为工作区。

工作区还必须与远端账号的 `~/.jumpserver233` helper 缓存完全分离，不能包含该缓存或位于缓存内部，例如直接授权整个 home 会被拒绝。helper 自身也不能位于授权树内，避免受限执行改写后续启动程序。

REST 创建/更新资产支持 `ssh_workspace` 字符串；更新时省略保持原值，空字符串关闭。只有资产管理权限可配置。托管账号继承主机工作区；访问票据与 SSH 会话绑定包含该字段，配置变化使旧绑定失效。SFTP 登录许可按用户、资产和账号授权，每次新建通道执行当前工作区策略；许可不证明远端目录 inode 或目录级审批。现有授权和命令过滤/审批继续生效。

```sh
jms exec ASSET_ID -- pwd
jms exec ASSET_ID -- 'printf hello > result.txt; cat result.txt'
jms ssh ASSET_ID
```

用户不需要持有远端密码，也不能从命令请求覆盖工作区。服务端在校验主机密钥的 SSH 通道中安装嵌入的摘要固定原生 helper，按内容 SHA 缓存，复用前校验；不向主机开放新端口、下载远端程序或常驻守护进程。

## 强制边界

- 远端 helper 通过 `openat2` 拒绝链接别名，持有目录 FD，使用同一对象设置真实 cwd 和 Landlock 规则。工作区子树可读写/执行，固定系统程序与库只读，额外仅提供加载器缓存、时区及终端/null 设备。不开放整个 `/etc`、其它 home、`/proc` 或 `/sys`。
- Landlock ABI 至少为 3，必须控制截断与跨目录链接/移动；seccomp 禁止网络 socket、进程注入/外部信号、命名空间/挂载、io_uring、共享 IPC 和危险设备 ioctl。shell、别名、脚本和后代进程继承限制；符号链接不能使目标内容访问越界，新建跨边界硬链接/移动被拒绝。
- 清空继承环境，只设置固定 PATH、语言、终端与工作目录；关闭 0/1/2 之外的 FD，清除 capabilities，设置 `no_new_privs`，root 执行也不能在 exec 后重新取得隐式 capabilities。不支持平台、内核或安装校验失败时拒绝执行，绝不回退普通 shell。
- SFTP 使用内置 Go 协议服务，先设置内核限制再自重启，所有 Go 线程继承同一边界。短暂传递密封 memfd，核对 PID 与工作目录设备/inode 后关闭；不符合启动链路则拒绝，不回退远端普通 SFTP。SSH/发现网关继续禁用。

## 受限文件管理

原有 `sftp` 授权、登录复核、传输限制和审计继续生效。文件管理中的 `/` 代表配置的工作区，而非主机根目录，界面同时显示实际工作区路径。协议处理器还通过 [Go `os.Root`](https://go.dev/doc/go1.24) 将文件与元数据请求限定在该树内，不向 SFTP 暴露 shell 的系统运行库例外。

支持列表、分页、下载、上传、新建目录、删除、追加和文件内偏移读写。普通重命名原子拒绝覆盖；显式覆盖上传使用 POSIX 原子重命名。协议中的链接创建、读取链接目标、权限/属主/时间修改被拒绝；Web 层继续拒绝路径穿越与符号链接。文件仅在已有权限范围内创建，不提权、不开放额外端口，也不依赖主机安装独立 `sftp-server`。

工作区是文件内容读写边界，不隐藏所有路径元数据，不是完整容器或 CPU/内存/进程数限额。`cd` 可能进入其它可遍历目录，但不会因此取得内容读写权限。系统程序/库是明确的只读例外，不能在其中放置需要隐藏的业务秘密。当前策略是整个目录树，不支持排除其中某个子目录。

已有硬链接和挂载到工作区的内容属于其授权范围；应使用专用目录，不能把敏感文件别名或挂载放入其中。内核路径访问语义见 [Linux Landlock 官方文档](https://kernel.org/doc/html/v6.6/userspace-api/landlock.html)。

Landlock 未控制的属主、权限、时间和 xattr 修改另由 seccomp 全局拒绝，包括工作区内；需要这些动作的工具可能失败，不能静默放宽限制。外部进程资源修改也被拒绝。

固定的账号改密、监控、插件和远端账号管理属于另行授权的管理通道，可能需要访问工作区外部；它们不向普通执行请求开放任意脚本。具有主机管理员权限或绕过跳板机直连的主体不受本工作区隔离。应使用专用远端账号并限制其它登录入口。

## 剩余范围

内核限制在启动 helper 时生效，不能追溯约束此前已经运行的普通远端进程。启用前先排空旧会话/作业并按主机策略停止遗留进程；配置变化不会将旧进程自动变成受限进程。

精确/正则目录的命令级规则、可信目录与审批绑定和资源配额仍待实现。不能将命令文本正则解释为文件系统权限，也不能把工作区能力当作完整企业版验收。实现与验证以[测试记录](./TESTING.md)为准，原命令规则见[命令过滤](./COMMAND-FILTERS.md)。
