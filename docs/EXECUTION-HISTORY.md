# 持久化执行历史

> 中文 | [English](./EXECUTION-HISTORY.en.md)

本批源码将普通 SSH 作业、Playbook 子作业及执行计划的终态历史移出热队列。单机使用内置 SQLite 索引，不需要额外服务；集群复用现有 PostgreSQL。当前代码及用例已编写，尚未执行统一验证。

## 保留与访问

- 热队列仍最多 1,000 条，达到 800 条后每次迁移最早的至多 64 条终态记录；Playbook 累积预留达到 18,000 步也触发迁移。活动执行、审批、派发及尚未收敛的取消不迁移。热队列全部为活动或专用采集任务时，继续执行既有容量限制。
- 普通作业保留完整命令、stdout/stderr、身份、目录证明及原请求 ID；执行计划保留完整步骤和当时的 Playbook 源码。旧源码移出热状态后仍可查询。
- `/api/v1/ops/jobs` 和 `/api/v1/ops/runs` 分页合并热记录与持久化记录；详情沿用现有路径和所有者权限。计划历史列表省略大段步骤，浏览器打开详情时单独读取完整记录。输出权限保持独立检查。
- 同一操作者、同一请求 ID 的重试查询历史回执，返回原作业/运行；改变原参数或运行来源返回冲突。历史运行不再参加派发，不重放远端操作。
- 先提交历史事务再删除热副本；热状态保存失败时保留原副本。查询按 ID 排除重复副本，重试迁移复用原记录。历史存储异常时不删除证据，不伪装成功或空结果。

## 存储

每个组织的 `execution-history.sqlite` 使用 WAL、完整同步和应用格式标识。正文与列表摘要压缩后以组织既有 AES-GCM key 加密；索引中的所有者、请求与正文摘要使用独立上下文的 HMAC，不保存明文凭据。按组织、种类、所有者和时间建索引，列表不读取完整输出。

单条正文最多 16 MiB、摘要最多 512 KiB；不自动淘汰历史。调用方应监测数据盘。目录、时间、记录 ID、索引身份及密文绑定共同校验；未知 SQLite/加密格式和错误 key 拒绝打开。PostgreSQL 使用组织 namespace/prefix 派生的隔离 scope，不新增连接池。

SQLite 物理 user_version 与加密 metadata 均为 1，未知版本拒绝打开。SSH 作业统计使用时间/ID 键集读取归档摘要，不加载输出正文；不增加独立报表事实表或永久统计仓库。

## 升级与恢复

Jobs 新写入格式为 v7，读取 v1–v7；Operations 新写入 v6，读取 v1–v6。旧程序不能读取新格式。回退必须恢复升级前完整数据和 key，不能仅替换二进制或删除历史数据库。

备份必须覆盖热状态、历史数据库和 key。停止服务后归档完整数据目录；运行中的 SQLite 数据库不能通过独立复制主文件获得一致快照，必须走支持一致性的备份入口。PostgreSQL 备份必须包含 `jms233_history_meta` 和 `jms233_history_records`，仅导出 JSON 文档不足以恢复历史。

## 待统一运行的用例

单机 `--check-data` 在监听和任务启动前逐条校验归档摘要/正文，包括停用及归档组织；内存按单条记录限制。缺失历史不创建空库，孤立 WAL/SHM、损坏或未知格式拒绝放行。停机备份保留数据库与 WAL/SHM；已编写进程退出、未 checkpoint 提交、恢复与原请求查回用例，尚未运行。

Testify 用例覆盖跨 1,000 条持续保留、所有者隔离、深分页、输出与源码恢复、持久化请求去重、修改重试冲突、事务回滚、热文件保存失败、崩溃双副本、密文/索引篡改、错误 key、重启、取消派发边界和 PostgreSQL 组织接管。编写用例不代表这些场景已经通过验收。
