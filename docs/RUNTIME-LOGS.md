## 默认即可运行

Go 服务自行写入 `JMS_DATA_DIR/logs/server.log`，不依赖系统 `logrotate`、cron 或额外常驻进程。达到 10 MiB 前轮转；跨 UTC 日期后的首次写入或每小时维护会轮转。保留最多 5 份历史、14 天，按先达到的限制清理。正常新写入每个文件不超过配置大小，超大单条记录截断并显示计数。已有超大旧日志会完整归档，按保留策略自然清理，不截断历史文件。保留量不限制业务审计的大小。

启动时清理过期历史；运行中每小时清理，即使没有新访问。只识别自身精确命名的普通历史文件，保留未知文件，不跟随日志文件符号链接。目录 0700、文件 0600；复用进程级目录锁，避免两个写入者共用日志目录。会话录像、命令/文件审计、业务数据与凭据不受本轮转操作影响。不要另配 `copytruncate` 或手工移动当前文件。

| 环境变量 | 默认 | 范围 |
|---|---|---|
| `JMS_LOG_DIR` | `JMS_DATA_DIR/logs` | 日志目录；`-` 仅输出到控制台 |
| `JMS_LOG_MAX_MB` | `10` | 1–100 MiB |
| `JMS_LOG_BACKUPS` | `5` | 1–30 份历史 |
| `JMS_LOG_DAYS` | `14` | 1–365 天 |
| `JMS_LOG_CONSOLE` | `true` | 同时输出控制台；进程管理器须自行限制控制台日志 |

集群模式默认仅控制台；显式开启本地文件时每个节点必须使用不同目录。macOS 部署自动使用部署根目录 `logs/`，保留现有 `server.log`，关闭控制台副本并把 launchd 的 stdout/stderr 接到 `/dev/null`，避免第二份无限增长的输出。启动前的参数错误由制品预检和健康检查反馈；Go 致命错误写入当前日志并在轮转时重新绑定；系统级崩溃输出不计为业务审计，异常记录可能临时超过单文件阈值，下一次启动会归档。所有调参需重启生效。

## 查看与操作

进入“设置 → 安全 → 运行日志”，查看用量、历史份数、当前保留策略、最近轮转和存储错误，可刷新或立即轮转。空文件轮转不生成空历史文件。界面复用现有紧凑设置卡片，没有引入新设计系统或动效。

全局管理员接口为 `GET /api/v1/settings/security/runtime-logs` 与 `POST .../rotate`。不提供日志内容或磁盘绝对路径。轮转输入包含进程 `instance`、`revision` 和 `request_id`；进程变化/旧版本返回 409，同一请求在最近 128 项窗口内重试不会再次轮转。磁盘错误返回通用错误码；检查磁盘空间/目录权限，修复后重试。只读查看不会清理文件。

运维按钮统一使用 `crypto.getRandomValues` 生成 UUID v4 请求标识，兼容内网 HTTP；不使用 `Math.random`，不降低凭据与审批校验。SSH、文件和审批接口契约保持原样。

实际 CI、BuildWorld、保数、日志轮转和清理结果见下方交付记录；精简证据保存在忽略的 `.cache/qa-reports/`。

统一 CI 发现角色管理页的长权限代码撑开 375px 布局，已补充 fieldset 收缩、权限文本换行和窄屏用例。仅有前端修复时，CI 的 `frontend_only` 手动入口现在仍运行完整生产浏览器套件；后端、race、集成与 Docker 复用源码未变化的已通过结果，不把跳过项算通过。
