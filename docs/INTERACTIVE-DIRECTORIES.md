# 交互 SSH 的可信提交目录

> 中文 | [English](./INTERACTIVE-DIRECTORIES.en.md)

配置 Linux [SSH 工作区](./SSH-WORKSPACES.md)后，Web SSH、`jms ssh` 和共享终端控制者使用同一原生 helper，为可识别的单行提交提供内核确认的 cwd。精确、子树、RE2 目录规则及审批复查共用既有命令策略。代码、Testify 用例和原生浏览器入口已编写，**尚未运行统一验证**。

## 原生通道

服务端复用固定主机密钥、摘要校验和内容缓存的 `jms-agent`，启动 `workspace-terminal`。SSH 通道不申请外层 PTY；helper 创建内部 PTY，子进程先进入既有 Landlock/seccomp 工作区再执行 `/bin/sh`。没有新增守护进程、监听端口、远端包管理依赖或公开 WebSocket 消息类型。

独立监督进程把 PTY 输出封装成数据帧，将目录请求、证明、提交和取消放入私有控制帧。打印伪造提示符、`PWD` 或控制帧内容不会生成证明。浏览器和 CLI 不能提交证明字段；管理会话只在私有连接内取得证明。公开认证方式、`X-JMS-ORG`、终端帧和录像格式保持原契约。

## 测量与提交

输入包含 Enter 时，服务端向 helper 申请一次性租约。helper 仅测量最初的单线程 shell：它必须仍是 PTY 前台进程组，stdin 仍指向保留的 PTY，并停在可重启的 `read(0)`。监督线程使用自己的 ptrace 关系停止子 shell，同时检查寄存器和空输入队列，防止前一条 `cd` 尚未执行时借用旧目录。Linux 接口见 [`ptrace`](https://man7.org/linux/man-pages/man2/ptrace.2.html)、[`proc_pid_syscall`](https://man7.org/linux/man-pages/man5/proc_pid_syscall.5.html) 和 [`waitid`](https://man7.org/linux/man-pages/man2/waitid.2.html)。

停止期间从 `/proc/PID/cwd` 打开真实对象，再通过工作区根的 `openat2`/`statx` 证明规范路径、根身份和目录身份。证明必须与已固定的资产工作区相符。远端 shell 不能读取监督进程的 procfs，不能通过 ptrace、共享 cwd 的独立进程、`setsid` 或终端输入注入替换该边界。

服务端在停止期间完成策略判断、加密审计、会话及共享控制者授权复查，再提交输入。helper 在写入前复查目录对象、前台组和输入队列，写入后才恢复 shell。同一租约相同提交返回原回执，不重复写入；改换内容、协议错误、未知回执或超过五秒的租约会关闭终端，不重试未知执行。

一次输入包只允许给一条可识别、最多 2048 字节的提交附加证明。多行粘贴、前台编辑器/程序、替换后的 shell、多线程 shell、不可测量目录及不支持的平台使用未验证状态；适用的目录规则保守拒绝。更高优先级的显式规则仍遵循原匹配顺序。伪装成密码提示的 shell 输入不记录秘密，也不能通过该提示绕开适用规则。

## 审批、共享和审计

命令审核沿用五分钟期限，不会一直冻结远端 shell。提交阶段保留待审文本并扣留 Enter，释放短租约；批准时重新申请证明、检查原目录对象及当前规则/授权，再发送 Enter。目录替换、重命名、规则变化、撤权或失去控制权会拒绝批准；重复消费审批返回既有一次性错误。

共享控制者使用相同输入入口，同时应用会话所有者与控制者的当前策略。审批和普通提交都在写入前复查权限。命令审计的加密内容保存证明；授权的命令列表额外返回 `working_directory` 和 `directory_verified`，中英界面显示“内核确认的提交目录”。旧审计记录没有这些可选字段，仍可读取。

## 支持范围

此证明表示**输入提交时原 shell 的 cwd**；受控 exec 的证明表示**命令起始 cwd**。二者不把命令文本解释成文件访问 ACL，不证明函数、别名、脚本、信号处理器或后代进程中后续 `cd` 的完整执行语义。文件访问仍由工作区和远端账号权限限定；资源配额另行配置。

原生目标是 Linux amd64/arm64，需要既有 Landlock ABI 3、`openat2`、目录创建时间身份，以及可用的 PTY、procfs、pidfd 和对子进程的 ptrace。主机 LSM/容器策略不允许时，不自动修改 sysctl 或提升能力；不能确认目录的提交继续遵循保守拒绝。普通、未配置工作区的 SSH 保持原方式，不能声称具备可信 cwd。

## 已编写的统一验证入口

- Testify：私有帧边界、短写、截断、证明校验、一次性回执、回执丢失不重发、伪造输出、超时关闭。
- Linux 原生：真实 cwd、伪造 PWD、队列中的 `cd`、同名目录替换、前台程序拒绝、关闭持有租约的进程及重复清理；系统调用夹具覆盖共享 cwd/FD 和 `setsid` 拒绝。
- Gateway/API：单行审计、多行拒绝、秘密提示、目录替换审批、审批重放、共享控制者当前策略及公开 JSON 不可伪造证明。
- `scripts/interactive-directories-qa.mjs` 复用 `native-package-qa.mjs` 的 SSH/API/原生制品，检查精确/子树/正则、真实审批、替换和审计；既有中英浏览器入口检查可信目录拒绝。没有另建测试栈或新增截图。

全部 42 组功能编写就绪后再运行上述入口和完整验证。清理两次会话、私有规则和严格限定的临时路径，沿用已有容器所有权检查及报告保留策略。当前没有新增通过率、性能或体积结论。
