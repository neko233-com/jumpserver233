# 组织与资源隔离

> 中文 | [English](./ORGANIZATIONS.en.md)

组织分别持有资产与加密凭据、节点、用户组、授权、命令过滤、资产/通道策略、SSH/SFTP 复核、在线终端、录像、文件审计、作业、模板和计划。平台用户、登录会话、身份源、Passkey、MFA、平台登录策略/复核和系统角色统一管理。竞品为 [JumpServer 企业版](https://www.jumpserver.org/enterprise.html)，完整对齐仍在推进。

## 默认组织与请求选择

默认组织 ID 为 `00000000-0000-0000-0000-000000000002`，与 [JumpServer 源码](https://github.com/jumpserver/jumpserver/blob/dev/apps/orgs/models.py) 一致。已有文件、凭据 key 和 PostgreSQL 文档继续作为默认组织的数据，无须搬迁。现有及新平台用户默认加入默认组织；显式移出会留下持久排除记录。默认组织不能停用或归档。

REST 使用 `X-JMS-ORG` 选择规范小写 UUID，缺省选择默认组织。重复、非法、GLOBAL/SYSTEM 虚拟 ID 不会降级到默认组织；未知、停用或归档组织返回 404，非成员返回 403。组织内不存在的资产、网关、作业和会话 ID 不会去其它组织查找。REST 的 `org` 查询参数不用于选择组织并会拒绝；WebSocket 使用服务器返回的非秘密 `?org=<uuid>`，票据仍通过既有子协议提交。组织参数与头不一致会拒绝。

浏览器顶部切换组织后重新加载控制台，关闭该页面的终端并清除旧页面状态；同浏览器其它标签页收到存储变更后也重新加载。组织选择保存在 `jms233.org`。失去当前组织资格时，选择器保留明确的重新选择入口。统一认证和退出不依赖当前组织成员资格。

Agent CLI 支持 `JMS_ORG_ID`，同时适用于 Bearer 和 AccessKey；客户端库可用 `WithOrganization(id)`。客户端不读取远端账号密码、私钥或导入口令。

## 系统角色与组织角色

系统管理员（兼容管理员账号及全局 system-administrator 角色）可访问所有启用组织。其它系统角色仍需组织成员资格；系统角色的资源权限在其可访问组织中生效。

组织成员可具有成员、组织审计员或组织管理员角色。组织审计员可读本组织资产和审计；组织管理员可管理本组织资源、成员和组织角色。普通成员依靠现有资产授权访问。组织角色仅能授予组织权限，不能创建平台管理员、修改身份源/MFA、管理平台登录复核或取得系统组织管理权。组织内名为 system-administrator 的内置角色也只含组织权限。

角色配置页分别为系统角色和组织角色。全局旧 `/api/v1/rbac` 管理路径保持兼容；显式系统路径为 `/api/v1/system/rbac`，组织角色为 `/api/v1/organization-rbac`。`/api/v1/rbac/me` 返回当前组织与系统权限的并集，并分别给出 `organization_permissions`、`system_permissions` 和 `organization_id`。实际接口使用服务端对应作用域的权限。

用户组分别持有组织成员。默认组织中的既有用户组可能已绑定系统角色；组织管理员不能借此修改系统角色组的成员或删除该组，需系统管理权限。组织资源授权和过滤规则的用户必须仍为组织成员。

## 管理、撤销和审计

`/api/v1/organizations` 支持列表、创建及修订更新；`/{id}/members` 提供成员读取和修订更新，使用统一用户 ID 或精确用户名添加已有用户。管理组织需要系统 `organizations.manage`；管理本组织成员需要对应作用域的 `organizations.members.manage`。`/{id}/audit` 提供分页变更记录。最多 100 个组织（含默认和归档组织）、每组织 10,000 个显式成员记录，保留最近 10,000 条变更审计。

成员角色 `none` 表示移出，包含默认组织的显式排除。后续资源请求和计划派发检查当前成员资格；在线 SSH 在输入及周期检查时拒绝已移出的成员。已有授权、组和角色配置保留，重新加入后会继续参与权限计算；重新加入前应检查这些配置。

停用组织会阻止新的资源访问，并停止该组织的监控、调度、作业和在线终端。已经进入远端的操作或文件传输可能按请求开始时的决定完成。DELETE `/{id}?revision=N` 归档并保留数据；POST `/{id}/restore?revision=N` 恢复后仍停用，需再显式启用。归档不是凭据或审计清除。

平台登录策略统一管理，界面的用户登录页签使用 `/api/v1/platform-access-policies`；资产和通道规则使用当前组织的 `/api/v1/access-policies`。组织管理员不能修改平台登录规则，其策略审计也不会显示平台登录记录。

## 单机与单活 HA

新组织使用 `JMS_DATA_DIR/organizations/<uuid>/` 的独立文件、审计目录和运行服务。加密存储 key 由主 Vault key 与组织 UUID 通过 HMAC-SHA256 派生；默认组织保持原 key。备份和恢复需保留主 key、组织元数据、对应目录及共享文档。相同主机地址、端口、固定主机密钥及用户名的密码资产，由活动节点协调远端改密并同步各保管库，包括停用和归档组织。凭据不一致时拒绝改密；相同私钥也会先提交全部副本再撤销旧钥，地址别名不会自动合并。详见 [密码轮换](./PASSWORD-ROTATION.md) 和 [密钥轮换](./SSH-KEY-ROTATION.md)。

PostgreSQL 在同一集群命名空间内使用 `<uuid>:<document-key>` 保存新组织状态，复用活动节点的数据库连接池；默认组织原文档保持原 key，新增组织角色单独作用域保存。单活节点接管后按组织恢复资源、成员、角色、模板和计划；在线 SSH/SFTP 会话不迁移。共享文件和选主要求见 [CLUSTER-HA](./CLUSTER-HA.md)。
