# SSH 受控执行目录与命令规则

> 中文 | [English](./EXECUTION-DIRECTORIES.en.md)

Web 工作台的单命令作业和 `jms exec` 支持在已配置的 SSH 工作区内选择执行起始目录。目录规则支持精确路径、目录子树和整路径 RE2 正则；审批绑定真实目录对象及当前命令策略。本批统一验证已通过，验收范围见[测试记录](./TESTING.md)。竞品仍为 JumpServer 企业版，完整企业版对齐继续推进。

## 配置和使用

先为 Linux 资产配置[SSH 执行工作区](./SSH-WORKSPACES.md)，例如 `/srv/work`，并在主机上创建 `/srv/work/deploy`。目录所有组件必须存在且不是符号链接。Web 工作台选择该资产后可填写“执行目录”；留空使用工作区根目录。

```sh
jms exec ASSET_ID --directory /srv/work/deploy --timeout 60 --json -- pwd
```

`POST /api/v1/ops/jobs` 新增可选 `working_directory`，必须是工作区内规范化的 Linux 绝对路径。Job 保留该请求参数；`execution_directory` 表示远端预检实际验证的目录。没有配置工作区的资产不能使用该参数，系统不会回退到 `cd` 字符串拼接。固定插件、账号收集和账号管理操作不接受自定义目录。

### 批量、模板、调度与 Playbook

本批实现将 `working_directory` 接入个人命令模板、计划与运行快照，覆盖 batch/once/interval/cron 和手动触发；新增部分正在等待统一验证，不沿用上方单命令的通过结论。Web 工作台提供目录输入及快照显示，CLI/SDK 使用相同 JSON 字段，例如 `jms ops create --file plan.json`。

命令模板保存目录；创建计划时冻结模板的命令、超时、目录与修订，不能用计划参数改写模板目录。模板以后修改或删除不改变旧计划；相同创建请求返回旧快照，改换目录返回 `409`。只修改调度不会改变目录。

创建计划只检查各目标配置的工作区范围，不连接 SSH，也不把输入字符串当作真实目录证明。手动触发/恢复计划复查当前权限；需要目录证明的命令交给实际子作业预检，已知拒绝继续拒绝。每个子作业共用前述固定连接、真实根/cwd、规则摘要和一次性审批。重启保留目录；已领取但结果不明的工作不会自动重放。

Playbook 的每个远端步骤使用计划起始目录，内部执行许可同时绑定 run/step/program、主机、命令摘要与目录；公开 JSON 不能伪造该许可。该目录不会跟随前一步的 `cd` 改变，也不会把 YAML `chdir` 转换成逐命令目录证明。命令过滤不支持的生成脚本在适用规则存在时仍拒绝，不因 Playbook 身份放行。

operations 加密 envelope 升为 v5；v1–v4 原有内容保持可读，旧格式夹带非空目录字段拒绝。新数据不能直接交给只支持 v4 的旧程序；升级/回退边界见[升级兼容范围](./UPGRADE-COMPATIBILITY.md)。

命令过滤表单新增执行目录范围，对应以下可选字段：

| directory_match | directory_pattern | 语义 |
|---|---|---|
| 留空 | 留空 | 保持原有命令规则 |
| `exact` | `/srv/work/deploy` | 只匹配这个起始目录 |
| `tree` | `/srv/work/deploy` | 匹配该目录及 `/` 分隔的后代，不匹配 `deploy-other` |
| `regex` | `/srv/work/releases/[0-9]+` | Go RE2 匹配完整起始路径 |

目录模式最多 256 字节；精确和子树模式要求规范化绝对路径。命令匹配、用户/组、资产/节点、账号、优先级和有效时间继续共同决定第一条匹配规则。更高优先级的显式允许规则继续有效。单机文件和 PostgreSQL 状态文档保存相同字段。

## 实际目录和审批

服务端经固定主机密钥的管理通道准备经过 SHA-256 校验的原生 helper。helper 从持有的工作区根 FD 使用 `openat2` 的 `RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS` 打开子目录；不会根据终端提示符、客户端 `PWD` 或推断的 `cd` 历史判断目录。路径解析语义见 [Linux openat2 手册](https://man7.org/linux/man-pages/man2/openat2.2.html)。

根和起始目录分别使用启动 ID、文件系统设备、inode 和 `statx` 创建时间证明身份。普通文件增删不改变证明；目录替换、身份能力缺失或主机重启会使旧证明失效。执行时再次打开和核对 FD，以同一 cwd 对象调用 `fchdir`，再启动受内核限制的命令。工作区根仍负责整个目录树的 Landlock 权限；[内核文档](https://docs.kernel.org/userspace-api/landlock.html)说明其文件系统控制语义。

新作业的内部 `cx2-` 上下文包含连接/网关快照、工作区根身份、起始目录身份和活动命令策略摘要。删除并重建同名规则也会改变摘要。登录复核许可按这个完整上下文一次性消费；命令审批在提交时保存上下文，批准时重新验证当前授权、策略和远端目录。SSH 连接/helper 准备完成后，发送用户命令前再检查授权。证明不匹配就拒绝，不会执行未受控命令作为回退。

作业以认证加密 envelope v6 保存目录字段和证明，继续读取 v1–v5。旧的 `cx1-` SSH/SFTP 许可保持兼容；旧普通作业若仍等待命令审批，需要取消后重新提交以绑定当前策略。SSH/SFTP 登录审批不会互相消费许可。

同一用户相同 `request_id` 和参数返回原作业；修改执行目录返回 `409`。重试原回执不重新连接主机、不消费第二个登录许可，也不重新执行命令。配置/目录变更后需要新请求时应使用新的 `request_id`。预检无法验证目录返回 `412`，已绑定对象改变返回 `428`，当前权限或策略不再允许审批返回 `403`。

## 终端与限制

配置 Linux 工作区的终端新增[原生提交目录证明](./INTERACTIVE-DIRECTORIES.md)，与批量/模板/计划/Playbook 贯通均待统一验证。原始 PTY 无法证明每条命令的 cwd。匹配目录规则的命令在 cwd 未验证时保守拒绝，并提示使用 Web 作业或 `jms exec --directory`；不能通过人工批准把未知目录当作已验证。存在适用规则时，无法识别的输入继续拒绝。共享终端与 Agent CLI 也接收该提示。

目录规则匹配**执行起始目录**，不表示某个文件路径的访问 ACL。命令仍能访问整个配置工作区；shell、脚本、别名、后代进程和后续 `cd` 的完整语义没有因此获得逐命令证明。目录授权跟随已持有的对象，不承诺执行期间命名空间路径永远不变。需要更小的文件范围时配置独立工作区和受限远端账号。原生交互证明仅覆盖输入提交时原 shell 的 cwd；任意 shell 内部执行语义与资源配额不在该证明范围内。

原生工作区继续禁止无法安全限定目录的元数据系统调用，包括时间戳修改。`touch` 可能先创建文件，再因时间戳操作被拒绝而返回失败。策略允许或审批通过不保证远端命令执行成功，需同时查看退出码与 stderr。
