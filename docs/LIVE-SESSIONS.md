# 在线终端监看

> 中文 | [English](./LIVE-SESSIONS.en.md)

审计台的活动终端可打开“实时监看”，只读显示连接后的新增输出。支持 SSH、Telnet 和 Kubernetes 终端。关闭监看不会关闭操作员会话。

## 权限与边界

- 操作员可监看自己的活动终端；跨用户需要独立的 `audit.sessions.monitor_all` 权限。仅有查看会话元数据、录像或中断权限均不能跨用户监看。
- 新权限可由系统角色或组织角色分配。内置系统管理员具备该权限；现有 `auditor` 角色不会自动获得新权限。
- 每次授权后签发 30 秒、单次使用的随机票据。服务端仅保存摘要，WebSocket 通过 `jms233-monitor-v1` 与票据子协议连接；票据不进入 URL、日志或 localStorage。
- 票据绑定会话、观看者、组织与签发来源。连接时、发送输出前及每秒空闲检查均复查当前身份、监看权限、组织资格和平台访问策略。
- 服务端不向监看者转发原始键盘输入。监看输出仍可能包含远端程序显示的敏感内容；因此跨用户监看属于独立授权。
- 监看端发送任何应用消息都会断开自身，不能执行命令、调整远端终端或关闭主会话。断开、票据重放和撤权均不影响操作员连接。

## 使用与资源

审计台 → 活动终端 → 实时监看。页面显示只读说明、连接状态及观看者 ID / 会话 ID 水印。水印用于识别页面截图，浏览器端样式不提供防篡改保证。

不发送历史屏幕快照或输入回放；可关闭监看后另行查看已结束的加密录像。窗口按操作员的终端尺寸显示，较小屏幕可以滚动。

每个会话最多 8 个等待或已连接的监看者，每个组织 Broker 最多 64 个。每个监看者最多缓存 32 个输出块（每块最大 16 KiB）；队列满会断开该监看者。浏览器也限制未渲染输出为 512 KiB。输出不等待监看客户端，不额外复制整份录像。

`monitor_started` 在输出发送前写入并同步会话审计索引；失败时不发送输出。结束时尝试写入 `monitor_ended`，记录观看者身份和时间，不记录票据和终端内容。存储故障可能使结束事件缺失。

## SSH 持续授权

SSH 在拨号前后、WebSocket 连接时、每次输入前和每 10 秒空闲检查时复查：当前用户/组/角色、资产或节点继承授权、授权到期、组织资格、来源/时段/通道策略，以及目标和逐跳网关的连接/凭据修订。删除授权、移出组、撤销角色、改变目标或凭据后，不再允许下一次输入，空闲连接最迟在下一次检查时结束。命令策略也重新读取当前用户组与节点范围。

凭据轮换会结束仍绑定旧修订的 SSH 会话，用户需重新连接。已下载的数据和已发送至终端的输出无法撤回。

外部身份源停用会使 SSH 或监看身份失效。命令等待审批期间若授权被撤销，批准也不能提交执行；若命令规则改为拒绝或改为另一条复核规则，则清除待执行输入并返回拒绝。

## API 与部署

- `POST /api/v1/sessions/{id}/monitor`：当前身份申请只读票据；不可见、未连接或已结束会话返回 404，容量限制返回 429。
- `GET /ws/api/v1/sessions/{id}/monitor`：单次票据连接。二进制帧为输出，文本帧为 `resize` 元数据。
- 单机优先；PostgreSQL 单活 HA 的监看权限沿用共享角色/组织配置，票据、队列及在线会话保留在当前活动进程。接管需重新建立 SSH 和监看连接，不支持多活路由或会话迁移。

终端与 RDP 的创建时水印及录像行为见 [交互会话安全](./SESSION-SECURITY.md)。完整企业版目标仍按 [PLAN](./PLAN.md) 推进；会话分享、协同输入与 RDP 实时监看尚未实现。
