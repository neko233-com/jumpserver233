# SSH 网关

> 中文 | [English](./GATEWAYS.en.md)

SSH 密钥安装、验证后轮换、显式启用的七天计划及持久化阶段恢复见 [SSH 密钥轮换](./SSH-KEY-ROTATION.md)。

目标资产与网关现支持导入 SSH 私钥：输入只写、保管库加密、公钥指纹及验证后恢复历史版本。密码轮换仍按密码凭据调度，详见 [SSH 私钥](./SSHKEYS.md)。

管理员可以将一台已登记的 SSH 资产设为另一台资产的网关。单机优先；网关引用与加密凭据使用现有资产存储，支持 PostgreSQL 单活 HA。竞品基线为 [JumpServer 企业版](https://www.jumpserver.org/enterprise.html)，完整企业版对齐仍按 [PLAN](./PLAN.md) 推进。

## 配置与连接

先登记外层网关的地址、账号、密码和通过可信渠道确认的 SHA256 主机指纹，再编辑目标资产，在“SSH 网关”中选择它。目标地址由最后一跳解析；平台不需要直接连接该地址。网关 SSH 服务必须允许访问下一跳的 `direct-tcpip` 转发。平台不向网关申请交互式 shell 或 SSH agent 转发。

每台资产可引用一个网关，最多三层，顺序为外层网关 → 内层网关 → 目标。服务端在创建、修改和加载时检查缺失引用、循环及深度；修改上游使既有下游超限也会被拒绝。仍被引用的网关不能删除（`409 ssh_gateway_in_use`）。API `gateway_id` 省略时编辑保留原值，空字符串显式清除。

每一跳分别使用保管库中的凭据认证并校验各自主机指纹。密码、私钥和内部路由不会包含在资产响应中。任一握手失败或超时会关闭整条连接；终端、文件会话或任务结束时也会关闭网关传输。

## 授权与审计

配置路由需要资产管理权限。管理员选择的网关作为平台连接基础设施使用；操作者只需目标资产相应的 `view`、`connect` 或 `sftp` 授权，无需获得网关的直接登录权限。目标登录复核、命令策略、任务派发时权限检查继续生效。网关资产自身的登录复核控制其直接登录，不作为下游路由的第二张审批单。网关配置应仅向可信管理员开放。

监控、Web SSH、Agent CLI、SFTP、命令/批量/计划任务、七天改密和凭据恢复共用同一路由连接器。SSH 会话索引记录建立连接时的 `gateway_ids`（从外至内），不记录网关密码。目标授权不会让操作者看到网关资产列表或凭据。

## 改密与高可用边界

网关存在未决改密/恢复记录时，新的下游连接暂缓；先恢复网关，再重试下游。已建立会话不会自动迁移；重启和 HA 接管后需重新连接。网关配置和加密凭据可恢复，不代表会话连续性或多活 HA。当前不包含独立网域对象、自动网关选择、自定义授权文件或生产网络故障演练。

## 验证

Testify 覆盖一至三跳实际 SSH 转发、逐跳主机指纹及认证、指标和命令、PTY/缩放、SFTP、改密及新凭据校验、超时关闭、图校验、持久化与 API 错误。HA 集成覆盖接管后路由引用与删除保护。Playwright 通过只在夹具网关内映射的 `private.synthetic.invalid` 验证表单、监控、目标独占授权、Web SSH、会话审计和 Agent CLI；不将合成夹具验证当作生产主机验收。统一入口见 [TESTING](./TESTING.md)。
