# 网站、游戏与服务账号保险库

> 中文 | [English](./PASSWORD-VAULT.en.md)

保险库存放网站、游戏与服务账号，按组织隔离，可选择个人私有或组织共享。数据由服务端 Vault key 使用 AES-GCM 加密；服务端可解密，Vault key 与数据由部署管理员保护。本功能不是端到端加密或 1Password 客户端兼容实现。停止写入后的现有数据目录备份包含保险库；恢复时需要同一 Vault key。

保险库 API 仅接受直连 TLS、本机回环连接，或通过受信任反向代理的 HTTPS：配置 `JMS_PUBLIC_URL` 为完整 HTTPS 源、在 `JMS_TRUSTED_PROXIES` 中指定代理网段，代理必须覆盖 `X-Forwarded-Proto` 和 `Host`。内网 HTTP 地址不能直接传输保险库数据。可在 Mac 本机使用回环地址；如网络允许，也可通过受控 SSH 隧道使用本机回环地址。

需要保留现有 HTTP 入口时，可将 `JMS_ADDITIONAL_HTTPS_ORIGIN` 设置为完整 HTTPS 源，并只信任会校验 Host、Origin 且覆盖转发头的反向代理。新入口的登录 Cookie 会标记为 Secure；原有入口保持原行为。不配置该选项时，不新增受信来源。

登录控制台后选择“账号保险库”，添加网站、游戏或服务账号。新建时默认为组织共享，可取消共享；共享记录的当前组织成员均可查看、修改、删除及授权 Agent，私有记录仅创建者可用。请只对可信任的组织成员共享。修改账号需要输入新密码；保存新修订后，旧授权失效。删除账号同时撤销其授权。查看密码、保存、删除、授权、撤销和读取都写入操作记录；列表只显示最近 100 条。

## Agent 接入

Agent 使用账号已有的平台会话或 AccessKey 认证，遵循 [认证](./AUTH.md) 的组织选择和凭据保护要求。创建时使用 `POST /api/v1/password-vault/items`，JSON 字段为 `kind`（`website`、`game` 或 `service`）、`title`、`site`、`username`、`password` 和 `request_id`；`request_id` 是 16 字节随机值的小写十六进制。同一用户对同一请求 ID 重试相同内容返回同一记录；不同内容返回 409。响应和列表不含密码。密码和令牌不要写入命令行、日志、提示词或共享会话记录。

用户在浏览器对指定账号点击“授权 Agent”，得到授权 ID 和令牌，有效期 10 分钟。通过安全渠道交给同一平台用户身份的 Agent；Agent 向 `POST /api/v1/password-vault/grants/{id}/consume` 发送 `{"token":"..."}` 并携带平台身份。授权只能读取对应账号的当前修订一次。成功读取、删除、撤销、过期或服务重启后不能再次使用；若读取响应丢失，用户需要重新授权。有效授权可在控制台撤销。浏览器会话签发授权；平台 API token 或 AccessKey 不能代替用户签发授权。

客户端应使用 HTTPS 或本机回环地址，不要将密码或授权令牌放在 URL 中。若用户或组织访问失效，Agent 的平台认证或组织授权会拒绝后续请求。

## 受控导入

`scripts/password-vault-import.py` 从标准输入读取 JSON 数组，使用私有文件中的平台 Token 写入指定组织；脚本只输出数量，不打印账号或密码。每项包含 `request_id`、`kind`、`title`、`site`、`username`、`password` 和布尔值 `shared`。导入前应从权威配置确认来源，生成稳定且唯一的请求 ID；相同内容可安全重试，内容改变时使用新 ID 并处理已有记录。脚本只接受经过系统证书验证的 HTTPS 或本机回环 HTTP，拒绝重定向；不要把实际数据写入本开源仓库或命令行。

有权使用节点服务令牌的本机管理员可在每项中指定 `owner_id`，将导入记录归属到该组织的现有活跃用户；服务只在无转发头的本机回环连接上接受此操作，并记录真实导入主体。普通平台 Token 和远程代理不能指定其他所有者。

先使用 `--dry-run` 验证所有输入；此模式不读取 Token、不连接服务，也不会保存密码。
