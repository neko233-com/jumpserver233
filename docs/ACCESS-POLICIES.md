# 登录与资产访问策略

> 中文 | [English](./ACCESS-POLICIES.en.md)

组织通过 `X-JMS-ORG`、浏览器切换和 Agent CLI 选择隔离资源、角色与运维审计，支持单机存储和 PostgreSQL 单活 HA。详见 [组织隔离](./ORGANIZATIONS.md)；完整企业版目标仍在进行。

控制台的「访问策略」提供用户登录、资产访问和连接通道三类规则。竞品也将登录 IP、时段和连接方式列入访问控制，参见 [JumpServer 官方说明](https://docs.fit2cloud.com/jumpserver/manual/admin/console/access_control/acls/)。规则在已有身份、资产授权和审批之外执行，允许规则不会新增资产权限。单机默认使用本地文件；PostgreSQL 单活 HA 共享配置、变更审计和拒绝记录。

## 匹配规则

- 用户：全部用户、指定用户或用户组。资产规则还可选具体资产、节点及其后代、SSH 账号。
- 来源：IPv4/IPv6 地址、CIDR、闭区间；一条规则内按任一地址匹配。留空或 `*` 表示全部。
- 时段：IANA 时区与每周星期/分钟窗口。开始包含、结束不包含；空列表表示全天，跨午夜用两个窗口。按该时区的夏令时转换，重复的本地时段均匹配。
- 动作：允许或拒绝；平台登录还支持需要审批与站内通知。每类按优先级从小到大选择首条匹配规则；同优先级拒绝优先，再按 ID 排序。三类分别检查，任一拒绝即停止。未匹配则继续原有授权链。
- 启停与修订：编辑、切换和删除均校验修订号。当前管理员会立即失去登录权限的配置变更被拒绝；未来时段仍按规则执行。配置全员时段限制前，应先建立所需管理员来源的高优先级允许规则。

## 服务端执行通道

| 通道 | 检查位置 |
|---|---|
| 凭据轮换 `credential_rotation` | 改密计划逐步执行、显式恢复、单账号密码/密钥轮换及历史密码恢复；特权账号也检查当前策略 |
| 交互 SSH | Web SSH、Agent CLI 共用的会话创建、WebSocket 票据附着、终端输入；在线连接每十秒再检查 |
| SFTP 访问 | 登录复核会话签发及每个文件请求 |
| 命令执行 | 工作台/CLI 的即时命令与批量任务 |
| 计划执行 | 一次性及周期计划实际派发 |
| 文件上传/下载/删除/创建目录 | 对应 HTTP 操作；先通过 SFTP 通道检查 |

通道由执行入口确定。Web SSH 与 CLI 交互会话共用 `ssh`，工作台与 CLI 命令共用 `exec`。客户端不能自报另一种类型来绕过策略。管理员同样受访问策略约束；角色的复核绕过权限仅影响原有登录复核。

作业和计划保留由 API 取得的原始来源。审批和实际执行按当前用户、组、节点和规则重新检查。调度器使用计划创建时的来源，并检查派发时的时段。既有计划/作业缺少来源时保持未知，遇到适用的来源限制便拒绝执行，需要重新创建。策略拒绝不会打开 SSH 或触碰远端文件。

新登录在发送 Cookie/Token 前检查策略；已登录 Cookie、Bearer、永久 Token 和 AccessKey 请求也经过平台登录规则。注销保持可用。在线 SSH 在规则拒绝时关闭并记录 `access_policy_denied`；正在传输的单个文件按请求开始时的判断执行。

## 反向代理

默认使用 HTTP 连接的远端地址。部署在反向代理之后时，可通过 `JMS_TRUSTED_PROXIES` 指定最多 32 个代理来源 CIDR，例如 `10.20.0.0/24,2001:db8:1::/48`。只有直接连接来自这些代理时才读取 `X-Forwarded-For`，从右向左取第一个不可信跳。代理必须正确覆盖/追加客户端地址。缺失、格式错误、超过 32 跳或过长的可信代理头产生未知来源，适用的来源限制会拒绝。其他转发头不会改变策略来源。

开发用 Vite 代理默认使后端看到回环来源。页面显示「API 识别的来源」供核对；生产反代与 HA 两节点需采用一致的可信代理配置。

## 管理、审计与验证

管理需要 `access_policies.manage`，内置管理员包含此权限。API 为 `/api/v1/access-policies` 的列表、创建、修订更新与删除；`/context` 返回当前服务端来源，`/audit?limit=25&offset=0` 提供分页审计。拒绝响应只返回稳定错误码，不公开匹配范围。每个配置文件最多 500 条规则，保留最近 5,000 条配置变更和拒绝记录；同一用户/规则/来源/通道的相同拒绝一分钟内合并。审计写入失败会阻止受限操作。

Testify 覆盖来源格式、代理链、防自锁、版本冲突、组/节点范围、优先级、DST、存储失败回滚、审计保留、审批来源、计划恢复及在线 SSH 策略撤销。PostgreSQL 与双节点用例检查接管后的规则和计划来源；Playwright 覆盖中英管理页、启停/编辑/删除、登录、Web SSH、CLI 和文件动作拒绝。集中运行入口见 [TESTING](./TESTING.md)。

平台登录还支持审批和站内通知，见 [平台登录复核](./PLATFORM-LOGIN-REVIEWS.md)。属性筛选、组织级规则、RDP 剪贴板和数据库结果脱敏仍在完整企业版目标中。规则文件/共享文档需与其他配置一起备份；误配未来时段导致失权时，停止相关节点并从有效备份恢复配置。
