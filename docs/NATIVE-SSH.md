## 使用

原生独立运行显式设置 `JMS_SSH_ADDR=0.0.0.0:2222`；开发与多实例测试默认不监听 SSH，避免抢占同机端口。外部 SSH 监听遵循现有非 loopback 配置要求，需要服务器已有的 `JMS_ADMIN_TOKEN`，它不发给 SSH 客户端。Docker 和 `Jenkinsfile_mac_single` 开启 2222。网页和 SSH 使用不同端口，不做协议嗅探。

```sh
ssh -p 2222 root@192.168.110.42
sftp -P 2222 root@192.168.110.42
```

首次安装默认平台身份为 root/root；旧实例保留现有账号与密码，启动和升级都不重置。用户名不是 macOS 的系统用户。TOTP 使用 keyboard-interactive；可通过 `ssh -o PreferredAuthentications=keyboard-interactive -p 2222 ...` 选择。需要首次 MFA 登记、短信/RADIUS 或平台登录复核的身份继续使用 Web 完成相应流程，原生入口不能绕过它们。

菜单默认中英同屏。直接输入关键词或 `/关键词` 搜索，多个空格分词同时匹配；title 映射现有 `name`，desc 映射 `remark`，IP 映射 `host`，账号也可搜索。输入列表编号连接，`r` 刷新，`n/p` 翻页，`q` 退出。输入 `exit` 退出目标 shell 后返回菜单。`ssh ... connect <account-id>` 可直接选择已授权账号，不执行任意跳板机系统命令。

SFTP 的 `/` 展示 `服务器名称--账号@稳定账号ID`，也接受 `/<account-id>/...` 的稳定路径。名称变化不影响稳定路径。标准 `ls/cd/get/put/mkdir/rename/rm/rmdir` 可用；上传/下载不增加端口。现有授权工作区和 SFTP 初始目录仍为远端边界，拒绝跨账号移动、越界及符号链接跟随。支持创建/覆盖的完整上传；不支持追加、原地部分修改、文件属性修改和任意 TCP/Agent 转发。

可在 SSH 用户名后附 `%<organization-UUID>` 选择已有组织，继续检查组织成员身份与资源隔离。普通单机用户无需配置组织。

## 安全、性能与清理

登录、搜索和会话创建走进程内 HTTP 管道，复用完整认证、源 IP、限流、组织、RBAC、授权、登录复核和会话策略。原生入口不持有超级管理员令牌。终端字节经过原有 WebSocket gateway，继续执行命令审批、拒绝、目录证明和加密录像。SFTP 通过不可从 HTTP 伪造的进程内回调进入同一文件授权入口；每个读写包复核权限和连接绑定，凭据留在服务端。

下载直接使用目标 SFTP 文件句柄，不落本地整份缓存。上传只在拥有 0700 目录中的 0600 临时文件暂存；最多两份、每份 1 GiB，拒绝有空洞的未完成上传，完成时使用既有服务的远端临时文件和原子重命名。断线、取消或失败均删除暂存，不覆盖原文件。正常关闭清理本批临时目录；崩溃后仅清理同 Vault 身份、明确标记且 OS 锁已释放的历史目录。它们位于系统临时目录，不进入业务备份。

SSH Ed25519 主机密钥由已有 Vault key 和专用域标识派生。保持同一 Vault key 时重启、升级和恢复都保持指纹；替换 Vault key 会改变指纹。最多 64 个客户端，每个客户端最多 4 个会话通道；握手限时 30 秒。活动原生客户端进入维护工作计数，发布前必须先关闭 SSH/SFTP 客户端，不强断已有操作。发布失败不自动重试。

验收辅助程序为 `server/testsupport/nativecheck`，仅从 stdin 接受配置，输出布尔结果、计数与散列，不输出密码、真实目标 IP 或终端原文。临时测试数据按归属清理，报告存放在忽略目录 `.cache/qa-reports/`。
