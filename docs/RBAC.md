# 系统角色与权限

> 中文 | [English](./RBAC.en.md)

主机插件新增 `plugins.inspect` 与 `plugins.manage`；它们仍需当前组织的目标账号 connect 授权。插件长任务在撤权后关闭 SSH，已分离的 Agent 需要显式停止，详见 [主机工具与 Agent](./HOST-PLUGINS.md)。

数据库查询的跨操作人元数据审计与取消分别由 `database.audit.view_all`、`database.cancel_all` 授权，复核沿用 `reviews.command.manage`；结果行只对当前仍获授权的所属操作人开放。见 [PostgreSQL](./POSTGRESQL.md)。

组织通过 `X-JMS-ORG`、浏览器切换和 Agent CLI 选择隔离资源、角色与运维审计，支持单机存储和 PostgreSQL 单活 HA。详见 [组织隔离](./ORGANIZATIONS.md)；完整企业版目标仍在进行。

角色管理 `/console/roles` 支持自定义系统角色、用户/用户组绑定和权限变更审计。既有 `admin/operator` 身份保持兼容：系统管理员拥有全部能力，操作员在既有资产账号授权之外，可以叠加系统角色。系统角色与当前组织角色分别管理，组织内角色和授权仅作用于该组织的资源。

初始化管理员后，本机匿名请求同样要求认证；没有 `JMS_ADMIN_TOKEN` 也不会回退为管理员，初始化前匿名身份创建的计划不再获得执行权限。

## 权限语义

- 多个用户角色和当前所属组角色取权限并集；缺省拒绝，不接受通配符或未登记权限。绑定与组成员变更在下一次 HTTP 请求或计划派发时重新计算，不把系统权限写入登录 Token。已经建立的 SSH 会话不会因角色撤销自动中断。
- 资产管理、全局清单查看、全局 SSH 执行、全局 SFTP、探测、改密和凭据备份是独立能力。`assets.manage` 可修改所有资产及凭据，包含清单查看，但不自动获得 SSH/SFTP 执行或备份恢复权限。全局连接/SFTP 权限包含必要的主机清单查看。普通用户仍可通过原有用户/组、资产/节点、账号、动作与时间授权访问部分主机。
- 审计查看、录像、命令、文件传输和中断会话分别授权；查看所有作业与取消所有作业也分别授权。读取他人计划/执行与管理他人计划分开。个人命令模板始终仅创建人可见。
- 管理用户的角色默认只能创建操作员；创建兼容管理员还需要 `roles.manage`。`roles.manage` 本身可以分配系统管理员角色，属于完整权限管理权。
- 登录复核默认仍生效，即使有全局 SSH/SFTP 权限；只有 `login_review.bypass` 可跳过。命令策略仍对全局连接角色执行。
- 全局 MFA 策略为 `admins` 时，持有任何系统角色权限的账号也在下一次登录时要求 MFA；设置挑战只能用于绑定，不能作为正常登录 Token。现有登录会话沿用既有策略生效时机。

## 内置角色

| 角色 | 能力 |
|---|---|
| 系统管理员 | 全部登记系统权限，兼容原有 `admin` 身份 |
| 审计员 | 全部清单/监控、会话/录像/命令/文件审计、作业及计划读取；不提供连接、改密、中断或取消 |
| 资产管理员 | 资产和凭据编辑、节点管理、清单查看及探测；不提供连接、改密、凭据备份恢复 |
| 访问复核员 | 登录复核、终端命令复核、SSH 作业复核及作业结果读取 |

内置角色不可编辑/删除。用户原始 `admin` 身份不能通过角色绑定撤销，因此不能误删最后的兼容管理员权限。完整权限目录由 `GET /api/v1/rbac/permissions` 返回，页面同时显示中英说明和权限 ID。

## 保存、版本与审计

角色更新、删除和绑定更新需要当前 `revision`，过期返回 409。仍被绑定的角色不能删除；空 `role_ids` 撤销该主体的角色绑定。用户/组必须存在。每次成功变更与包含前后快照、认证操作人和时间的审计在同一状态保存中提交；失败不改变有效授权。返回对象不会暴露可修改存储的切片引用。

单机保存到权限为 0600 的 `rbac.json`，单活 HA 保存到 PostgreSQL `rbac` 文档，不依赖远端服务。角色元数据和审计不包含 SSH 密码、Token 或 Secret。当前最多 100 个自定义角色、2000 个主体绑定和 10000 条变更审计；达到上限拒绝新增变更，不自动删除历史。审计归档/保留策略仍待实现。

## API

| 接口 | 用途 |
|---|---|
| `GET /api/v1/rbac/me` | 当前身份、角色 ID 和有效权限；所有已认证账号可用 |
| `GET /api/v1/rbac/permissions` | 登记权限目录 |
| `GET/POST /api/v1/rbac/roles` | 列表/创建角色，内容 `{name, description, permissions}` |
| `PUT /api/v1/rbac/roles/{id}` | 更新角色，增加 `revision` |
| `DELETE /api/v1/rbac/roles/{id}?revision=N` | 删除未绑定的自定义角色 |
| `GET/PUT /api/v1/rbac/bindings` | 列表/保存 `{subject_type: user|group, subject_id, role_ids, revision}` |
| `GET /api/v1/rbac/audit?limit=50&offset=0` | 变更审计，单页最多 100 条 |

除 `me` 外，以上接口需要 `roles.manage`。所有身份入口（Cookie、Bearer、永久 Token、HTTP Signature）均在服务端重新解析权限，客户端不能通过提交 `role` 或隐藏按钮绕过校验。

## 验证

Testify 覆盖权限并集、组成员撤销、版本冲突、内置角色保护、用户管理员提权拒绝、审计员不能中断/取消、存储失败回滚、返回切片隔离、并发更新和 PostgreSQL 恢复。双节点 HA 测试验证角色在接管后保留。Playwright 通过管理页面创建角色、绑定隔离合成账号，再验证仅用户管理页可用、伪造管理员创建被拒绝，以及已有登录会话在绑定撤销后立即失权。统一入口见 [TESTING.md](./TESTING.md)。
