# SSH 跳板机稳定版

> 中文 | [English](./SSH-FIRST.en.md)

2026-10-19 用户确认：先交付够用、稳定、低依赖的企业级 SSH 跳板机。竞品仍为 [JumpServer 企业版](https://www.jumpserver.org/enterprise.html)，完整企业版功能作为长期参考；其他协议、云厂商和复杂企业功能不作为本次稳定版的前置条件。本文调整近期交付顺序，不代表下列待完成能力已经实现。

## 默认部署

单机优先。当前默认使用 `JMS_DATA_DIR` 下的本地持久化文件和 Vault key，无需外部数据库、Redis 或常驻 Node。Go 通过 `JMS_WEB_DIR` 在同一端口提供静态网页、API 和 WebSocket。现有文件格式继续兼容；若后续引入 SQLite，必须提供可验证、可恢复且重复执行安全的迁移，不能要求用户手工重建资产或凭据。

PostgreSQL 仅作为显式启用的集群单活热备选项，配置与生产边界见[集群高可用](./CLUSTER-HA.md)。单机安装不得因集群能力而要求部署 PostgreSQL。

## 数据与命令安全边界

`JMS_DATA_DIR` 中的 Vault key 与加密数据必须一起恢复；使用外部 `JMS_VAULT_KEY` 时还需独立保管相同密钥。已有[凭据历史备份](./PASSWORD-ROTATION.md)仅用于远端账号恢复，不等于整站导出。不能直接复制正在写入的目录并宣称是一致性备份。

现有 [PTY 命令过滤](./COMMAND-FILTERS.md)适合常见交互输入的审计和拦截。任意 shell、别名、脚本、符号链接、命令替换以及 root 权限都影响目录语义。需要强目录限制时应采用可信 Agent/受控执行通道，并结合远端账号权限或隔离机制；可见终端提示符、`PWD` 环境变量或命令字符串不能成为唯一依据。规则未覆盖的通道必须明确标出，不能静默放行后宣称已受保护。

## 交付纪律

先完成同一批实现，再统一做 Go/Testify、race、生产浏览器和隔离 Docker 验证；覆盖幂等、版本冲突、重启和恢复。保留必要报告，清理本次归属明确的测试资源并验证重复清理安全。中英介绍、文档和自动语言识别继续维护。当前不发布内网；本范围验收通过后再发布一次正式版本。
