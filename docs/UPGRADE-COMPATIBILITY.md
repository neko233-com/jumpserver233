## 格式与拒绝规则

| 对象 | 当前支持边界 | 不支持时的处理 |
|---|---|---|
| 原生包 | manifest schema 1；受控安装要求 preflight/activation protocol 1 | 暂存核对全部路径、摘要、平台和权限；协议不兼容拒绝安装 |
| 业务数据 | 目标程序逐个打开并验证其已知格式，语义迁移由对应模块负责 | 未知/损坏/超限格式使离线预检失败；不以来源版本字符串推断可迁移 |
| 作业 | 加密 envelope 1–6；目录证明需要 v6 | 旧格式不得通过新增 JSON 字段获得目录执行语义 |
| 批量/调度/Playbook | 加密 envelope 1–5；非空目录快照要求 v5；原生 Playbook 要求 v4+ | v1–v4 可读取其原有合法内容，非空目录字段拒绝；正常变更写入 v5 |
| 整站备份 | 归档格式 1、完整性及 Vault key 绑定 | 错误口令、未知格式、非法路径或损坏包不覆盖现有业务数据 |
| 降级 | 已受管版本拒绝降级、同版本不同构建及数据目录改绑 | 放行前只能连同旧快照恢复；放行后保留新数据并向前修复 |

旧程序通常不能读新格式，不能只替换可执行文件回退。新操作目录首次写入 v5 后，回到只支持 v4 的程序必须恢复对应旧数据快照；不能让旧程序忽略目录字段后执行。

## 本批固定验收证据

- 历史真实服务创建用户、授权、七天轮换时间、SSH 审计、命令模板和一次性计划；升级后核对身份、权限、凭据 key、调度时间和快照，执行真实 SSH。
- 将 operations envelope 改为未来版本 999，执行正式安装事务路径；目标预检必须拒绝，保留原文件字节及原版本。恢复已知合法文件后升级；同一请求重复执行返回原回执。
- 对 v1–v4 的合法 operations 文档逐一读取并写入 v5；旧 envelope 中伪造目录字段要拒绝且不改原文件。
- 首次启动失败恢复旧数据和旧服务；放行后的失败保留新写入。备份导入、重复恢复、修订冲突、审批重放和资源清理使用既有统一入口。

离线预检没有端口、后台任务或远端业务动作。备份仍要求停机；在线热备、PostgreSQL 集群备份、生产多活及所有历史版本任意互迁没有因此完成。当前进度见[固定清单](./PROGRESS.md)。
