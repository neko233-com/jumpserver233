> 中文 | [English](./UPGRADE-COMPATIBILITY.en.md)

## 正式支持线

首个正式稳定版建立发布版本支持线。本批收尾前（2026-10-21）通过 GitHub Release API 复核，正式 Release 列表为空；manifest 的 `0.1.0` 是未发布基线。更早 Alpha/开发构建按实际格式预检，不承诺按版本号兼容，也不要求删除业务数据重建。

后续每个稳定版必须标明上一正式标签、源码 SHA、归档摘要和数据格式，保留实际旧版到候选版的升级、导出/导入及回滚证据。同一源码重编号的 `v0.0.x` 包只证明安装事务路径，不能冒充历史正式发布迁移。

## 已知格式与拒绝策略

| 对象 | 当前支持边界 | 不支持时处理 |
|---|---|---|
| 原生包 | manifest schema 1；preflight/activation protocol 1 | 核对路径、摘要、平台和权限；不兼容拒绝安装 |
| SSH 作业 | 读取 envelope v1–v7，新写 v7；目录证明要求 v6+ | 旧格式夹带新语义、损坏或未知版本拒绝 |
| 批量/调度/Playbook | 读取 envelope v1–v6，新写 v6；非空目录要求 v5+，原生 Playbook v4+ | 保留模板/源码快照；旧格式夹带目录拒绝 |
| 内置执行历史 | SQLite application_id `0x4a4d5333`、user_version 1、加密 metadata/正文 1 | 错误 key、未知格式、损坏、孤立 WAL/SHM 拒绝；缺失时不创建空库 |
| 整站备份 | 归档格式 1、完整性及 Vault key 绑定 | 错误口令、未知格式、非法路径或损坏包不覆盖现有数据 |
| 其他业务状态 | 各模块离线逐个打开、验证其已知加密格式 | 不根据版本字符串推断可迁移；任一失败阻止放行 |
| 降级与回滚 | 已受管版本拒绝降级、同版本不同构建及数据目录改绑 | 放行前完整恢复旧快照；放行后保留新写入并向前修复 |

旧程序不能静默忽略新字段继续执行。回退必须恢复匹配的完整数据、历史和 key，不能只换可执行文件或删除历史库。重启后需要重新登录；业务数据和执行回执保留。

## 本批实际证据

- 完整 Go/Testify 通过：逐条历史摘要/正文预检、停用/归档组织、损坏/未来格式及孤立 WAL 拒绝；原生子进程提交后直接退出，停机备份恢复 WAL、原请求查回及重复导入保留后续记录。
- Operations v1–v4 合法文档迁移写入 v6，伪造目录字段拒绝且原字节保留；当前历史写入格式由独立用例覆盖。
- 原生完整入口通过：未来 envelope 999 预检拒绝且保留文件字节；用户、授权、Vault、审计、模板/计划快照、真实 SSH、试运行失败回滚、放行后新数据保留和向前恢复。
- 定时与自动安装经过实际停机/快照/重启/验收，重复请求和重启不重复安装。

源码、报告、跳过项和六平台边界见 [mini 验收报告](./MINI-ACCEPTANCE.md)。固定历史源码 `4367285202054181344e386096b89e8ea3059703` 的旧演练仅作历史证据；本批默认入口不重新构建它。需要独立复核时使用 `node scripts/native-package-qa.mjs --batch historical-upgrade --historical`，不能把未运行入口写成已通过。
