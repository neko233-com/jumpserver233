## 支持线

2026-10-21 通过 GitHub Release API（`gh release list --repo neko233-com/jumpserver233 --limit 5 --json tagName,publishedAt,isDraft,isPrerelease`）复核，结果为空；本地也没有发布标签。`.release-please-manifest.json` 的首版基线为 `0.1.0`，尚未发布。首个稳定版建立支持线，不承诺更早 Alpha/开发构建按版本号兼容；已有数据在完整备份保护下走实际格式预检，不要求删除重建。

固定历史源码基线为 `4367285202054181344e386096b89e8ea3059703`。它是已有 Linux 原生升级演练的来源；`v0.0.0 → v0.0.1` 只是隔离演练标识，没有创建正式 Release。该基线到本批候选的验证由 `node scripts/native-package-qa.mjs --batch ssh-stable-closing --historical` 执行，结果以[测试记录](./TESTING.md)为准；本文件描述支持约束，不把新增用例写成已通过。

首个正式稳定版建立发布版本支持线。后续每个稳定版必须明确上一正式稳定版的标签、源码 SHA、归档 SHA 和格式，保留真实升级、导出/导入和回滚证据。不能把两个相同源码重新编号的包当作跨版本迁移。未验证的历史版本不承诺兼容，也不要求用户删除数据重建。

## 格式与拒绝规则

| 对象 | 当前支持边界 | 不支持时的处理 |
|---|---|---|
| 原生包 | manifest schema 1；受控安装要求 preflight/activation protocol 1 | 暂存核对全部路径、摘要、平台和权限；协议不兼容拒绝安装 |
| 业务数据 | 目标程序逐个打开并验证其已知格式，语义迁移由对应模块负责 | 未知/损坏/超限格式使离线预检失败；不以来源版本字符串推断可迁移 |
| Windows/数据库 PAM 资产 | 新增资产 envelope 5，读取原数组及 v2–v5；PAM 身份、采集账号/绑定与恢复字段要求 v5 | 旧格式夹带新字段拒绝；写入 v5 后旧程序必须恢复升级前完整快照；纳管回执、加密凭据与待确定结果保留；用例已编写未运行 |
| 用户与短信 MFA | 用户写入 envelope 4，读取旧数组/v2/v3/v4；短信状态加密 envelope 1 | 旧用户格式夹带短信字段拒绝；启用策略先写 v4 用户边界，旧程序拒绝 v4；新增迁移/接管用例未运行 |
| AI 助手 | 独立加密 envelope/state 1；离线 Open 只验证，实际运行才恢复孤立意图 | 未知格式/损坏拒绝；中断请求不重发，旧程序不具备此模块；回退使用升级前完整快照 |
| 作业 | 读取加密 envelope 1–7，新写入 v7；目录证明要求 v6+；索引历史格式 1 | 旧格式不得夹带新执行语义；回退保留升级前完整热状态、历史和 key |
| 内置执行历史 | SQLite application_id `0x4a4d5333`、物理 user_version 1、加密 metadata/正文 envelope 1 | 离线预检逐条校验摘要/正文，含停用及归档组织；未知格式、损坏、密钥不符或孤立 WAL/SHM 拒绝；不创建缺失历史，不重放执行 |
| 批量/调度/Playbook | 读取加密 envelope 1–6，新写入 v6；非空目录要求 v5+；原生 Playbook 要求 v4+ | 历史终态运行连同源码迁移到索引；未知格式拒绝，新增迁移用例尚未运行 |
| 既有报表回执 | 保留原 envelope/state v1 及 CSV 统计；本批 PDF/邮件/调度/统计仓库扩展已撤回 | 不为 mini 新增报表格式、外部服务或后台调度 |
| 整站备份 | 归档格式 1、完整性及 Vault key 绑定 | 错误口令、未知格式、非法路径或损坏包不覆盖现有业务数据 |
| 原生企业通知 | 现有通知 envelope 1 新增提供方配置及加密设置回执；新版读取省略这些字段的旧文档 | 已写入新字段后，不承诺旧程序可读；降级必须恢复升级前数据快照，不能删除新配置或回执 |
| 降级 | 已受管版本拒绝降级、同版本不同构建及数据目录改绑 | 放行前只能连同旧快照恢复；放行后保留新数据并向前修复 |

旧程序通常不能读新格式，不能只替换可执行文件回退。新操作目录首次写入 v5 后，回到只支持 v4 的程序必须恢复对应旧数据快照；不能让旧程序忽略目录字段后执行。

## 本批固定验收证据

本批新增离线历史逐条完整性检查、损坏/未来格式及孤立 WAL 拒绝、停用/归档组织覆盖；原生子进程提交后直接退出，验证 WAL 随停机备份恢复、原请求查回和重复导入保留后续新数据。源码与 Testify 已编写，尚未统一执行。

- 历史真实服务创建用户、授权、七天轮换时间、SSH 审计、命令模板和一次性计划；升级后核对身份、权限、凭据 key、调度时间和快照，执行真实 SSH。
- 将 operations envelope 改为未来版本 999，执行正式安装事务路径；目标预检必须拒绝，保留原文件字节及原版本。恢复已知合法文件后升级；同一请求重复执行返回原回执。
- 对 v1–v4 的合法 operations 文档逐一读取并写入 v5；旧 envelope 中伪造目录字段要拒绝且不改原文件。
- 首次启动失败恢复旧数据和旧服务；放行后的失败保留新写入。备份导入、重复恢复、修订冲突、审批重放和资源清理使用既有统一入口。

离线预检没有端口、后台任务或远端业务动作。备份仍要求停机；在线热备、PostgreSQL 集群备份、生产多活及所有历史版本任意互迁没有因此完成。当前进度见[固定清单](./PROGRESS.md)。
