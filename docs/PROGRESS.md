## 当前结论（2026-10-21：mini SSH 范围修正）

当前目标是中小公司单机部署、少依赖、易用、安全高效的 mini SSH 跳板机，权威范围见 [PRODUCT-SCOPE](./PRODUCT-SCOPE.md)。用户明确修正需求后，当前主目标从企业版 42 组改为现有 SSH 的 S01–S12，共 12 项；这不是新增完成，也不再把竞品功能全部作为待办。

本轮新写的 Azure/Google/OpenStack 云同步扩展及接口已撤回；同批尚未发布的 PDF/邮件报表、调度与永久统计仓库也已撤回，恢复原有统计/CSV。保留 SSH 作业/计划加密历史、请求去重及目录安全，新增离线逐条校验与 WAL 备份恢复用例。源码尚未统一验证，不能用旧结果代表当前版本。

先完成 mini 稳定版必要实现，再做一次统一验证、修复回归与清理；不再等待原 15 组企业扩展。当前剩余重点为 S10 目录链路验收、S11 更新支持版本/保数边界、S12 中英 UI、性能体积、Docker/浏览器、幂等清理与最终交付。

百分比等于“已闭环能力组数 / 固定清单总数”，按整组验收，不给部分实现折算分数。它不是代码量、剩余工时或生产可用性百分比；各组工作量不同。新增、删除或拆分分母必须注明需求来源、原因和前后数量，不能靠缩小口径提高进度。原厂支持服务、商业授权和供应商 SLA 不计入软件功能分母。

## 剩余收尾顺序与测试门禁

1. **先完成 mini SSH 稳定版必要实现、用例和双语文档。** 补齐 S10/S11 与核心 UI、维护便利性；不继续云同步等竞品扩展。历史 Release 不存在时明确版本支持边界，不制造迁移证据。
2. **全部实现就绪后，再执行一次统一验证。** 此前不运行测试、构建、浏览器或 Docker 验证。预先编写幂等、修订冲突、审批重放、重启、恢复和跨模块用例；最终集中运行现有入口。失败后修复并复验受影响项，只有共享路径影响或未解失败才扩大回归。
3. **清理并交付。** 保留摘要与必要截图，安全且幂等地清理自有测试资源，提交推送验收通过的范围。内网部署继续取消；满足 mini 门槛后再正式发布一次，changelog 只随 release 生成。

每次交付必须更新本文件，并在用户可见结论中写明：**当前范围、已闭环/总项数与比例、本次增量、剩余具名缺口、实际验证源码和未验证改动**。新增需求要说明它改变哪项范围。不得在缺少这些信息时连续开启下一批功能和完整回归，也不能把“测试通过”代替“全部功能完成”。
