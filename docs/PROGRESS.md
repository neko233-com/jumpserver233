## 剩余收尾顺序与测试门禁

1. **先完成 S10、S11 的全部代码、用例和双语文档。** 保留并完成当前目录改动；固定真实目录证明、审批/权限与幂等边界。升级固定支持矩阵和实际历史制品；若没有可用正式历史 Release，明确最低支持版本及不支持格式的拒绝，不制造“历史 Release 已验收”的结论。
2. **然后执行 S12 的一次统一验收。** 复用现有 Go/Testify、race、生产浏览器、原生安装/备份/升级和 Docker 入口；集中启动相互独立的检查，避免重复构建、重复建环境。幂等、修订冲突、审批重放、重启和恢复全部列入预先写好的用例。失败后修复并复验受影响项，只有共享路径影响或未解失败才扩大回归。
3. **清理并交付。** 保留摘要与必要截图，安全且幂等地清理自有测试资源，提交推送验收通过的范围。内网部署继续取消；正式发布与 changelog 遵守既有发布授权和流程。完整功能基线目前有 26 组缺口；本轮只处理稳定版涉及的部分，其他企业扩展后续按需推进。

每次交付必须更新本文件，并在用户可见结论中写明：**当前范围、已闭环/总项数与比例、本次增量、剩余具名缺口、实际验证源码和未验证改动**。新增需求要说明它改变哪项范围。不得在缺少这些信息时连续开启下一批功能和完整回归，也不能把“测试通过”代替“全部功能完成”。
