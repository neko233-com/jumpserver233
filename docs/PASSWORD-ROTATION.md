# SSH 密码自动轮换

> 中文 | [English](./PASSWORD-ROTATION.en.md)

SSH 密钥安装、验证后轮换、显式启用的七天计划及持久化阶段恢复见 [SSH 密钥轮换](./SSH-KEY-ROTATION.md)。

目标资产与网关现支持导入 SSH 私钥：输入只写、保管库加密、公钥指纹及验证后恢复历史版本。密码轮换仍按密码凭据调度，详见 [SSH 私钥](./SSHKEYS.md)。

SSH 网关现支持最多三跳，监控、Web SSH、CLI、SFTP、任务和改密共用逐跳指纹校验连接。配置与加密凭据支持单机及 PostgreSQL 单活 HA，详见 [SSH 网关](./GATEWAYS.md)。完整企业版对齐仍在推进。

管理权限可通过 `assets.rotate`（手动轮换）、`assets.backups`（备份/恢复）及 `assets.manage`（资产/凭据编辑）分别委派，详见 [RBAC.md](./RBAC.md)；接口仍不返回凭据明文。

## 当前能力

纳管的 Linux SSH 账号默认每 7 天自动轮换一次密码。管理员也可以在资产页手动发起轮换。轮换时间从资产创建或最近一次经验证成功的改密时间开始计算；普通操作员看不到轮换时间或轮换操作。

调度器随资产监控服务运行，每个进程最多并发处理 4 台主机。失败轮换的最近尝试时间和结果保存在资产存储中，因此普通轮换的 1 小时重试退避在服务重启和单活 HA 接管后仍生效。若存在加密的待提交凭据，服务启动时会先核对新旧凭据；恢复仍未解决时至少间隔 1 小时再试。开启集群模式后，只有持有 PostgreSQL 选主锁的活动节点会加载资产服务并运行调度器；资产清单及加密凭据保存在 PostgreSQL 共享状态文档中，Vault key 通过 `JMS_VAULT_KEY` 在节点间共享。轮换日志仍位于所有节点共用的 `JMS_DATA_DIR`。当前集群是单活热备，详见 [CLUSTER-HA.md](./CLUSTER-HA.md)。

## 同一账号的多个纳管副本

同一规范化主机地址、端口、固定主机密钥指纹和 SSH 用户名的密码资产（含同一组织内的副本），由活动节点统一协调改密。各副本的当前密码必须一致；新增或编辑冲突凭据返回 `409 shared_credential_conflict`，不会取用其他组织的凭据或修改远端。资产页的“账号协同改密”提示仅向有资产管理、改密或保管库管理权限的身份展示，不列出其他组织的名称或资产。

统一流程先将操作决策及新旧凭据写入根目录 `shared-passwords.json`（集群使用 PostgreSQL `shared-passwords` 文档），凭据以 Vault key 的 AES-GCM 加密，绑定操作 ID 和用途。再为全部副本保存加密待提交密码，最后才执行一次远端改密。验证后持久化提交决策，再依次更新各组织保管库；每个副本保留自身历史、版本、七天计划和本地审计，审计以统一操作 ID 关联，不复制其他组织的资产信息。

准备阶段中断会撤销待提交凭据；改密结果不明会保留新旧密码并每小时核对；已验证的提交决策会在重启或单活 HA 接管后继续完成本地提交，不再次改动远端密码。未解决操作只阻止相关账号的编辑、删除与新改密。停用或归档组织仍接收相同账号的已验证密码，但不启动其监控或任务。

主机 DNS 别名与 IP、不同 SSH 端口不会自动合并；需要使用一致的纳管地址。同一主机密钥不能克隆到不同机器，否则无法可靠区分其身份。相同私钥的副本也支持先提交全部保管库再撤销旧钥，详见 [密钥轮换](./SSH-KEY-ROTATION.md)。不同私钥的授权生命周期独立。自动七天调度的并发上限仍为每组织四个工作项，远端凭据变更由活动节点统一串行执行。

## 主机改密权限

- 目标主机需要运行 Linux，并允许纳管账号通过已固定的 SHA256 SSH 主机密钥登录。
- `root` 账号通过 `chpasswd` 更新密码；普通账号需要配置免交互的 `sudo -n chpasswd` 权限。
- 账号名及主机密码策略必须接受生成的 URL-safe 密码。轮换不依赖远端安装 agent。

如果 SSH 主机不可达、主机密钥不匹配、认证失败或账号无权运行改密命令，轮换会失败并保留当前有效凭据；管理员可以修复原因后手动重试。若状态为“需要恢复处理”，服务会每小时自动重新核对新旧凭据；解决前不要再修改该资产的密码。

## 凭据与恢复

新密码由加密安全随机数生成，只通过已验证主机密钥的 SSH 加密通道 stdin 传给 `chpasswd`，不会放入命令参数、环境变量、浏览器响应或审计记录。Vault 使用 AES-GCM 加密保存当前凭据和轮换中的待提交凭据。

远端改密结果不明确时，服务会分别尝试用新旧凭据认证：新密码通过后提交 Vault；旧密码通过后撤销待提交密码；两者都无法验证时保留加密的待提交凭据并标记“需要恢复处理”，不会覆盖当前凭据。服务每小时重试恢复，重启后也会再次尝试。

## 凭据备份与恢复

管理员可在资产“更多 → 凭据历史”中创建、查看、删除加密备份，或将账号恢复为选定备份。备份密码使用 Vault key 以 AES-GCM 加密，API 和页面只返回备份 ID 与创建时间，不显示密码。系统最多保留 10 个版本；手动备份达到上限后需要先删除旧备份，自动密码替换和成功轮换会先备份当前密码，并在达到上限时淘汰最早版本。

恢复不会直接把历史密码写为当前凭据。服务会先将备份密码作为加密的待提交凭据保存，再用当前凭据通过已固定 SHA256 主机密钥的 SSH 连接修改远端密码，并重新连接验证备份密码。验证成功后才将其设为 Vault 当前凭据；结果不明确时保留当前凭据和加密的待提交密码，沿用每小时恢复流程。审计记录操作者、备份 ID、结果和时间，不记录密码。备份管理及恢复 API 仅管理员可用，并禁用响应缓存。

轮换事件写入 `${JMS_DATA_DIR}/credential-rotations/index.jsonl`，记录资产、账号、触发方式、时间和稳定错误码，不记录密码。轮换 API 为 `POST /api/v1/assets/{assetID}/password-rotation`，仅管理员可用，响应禁用缓存且不包含密码。

## 验收边界

单机模式下，自动调度、SSH 改密、主机密钥校验、凭据确认、失败恢复、审计及管理员 UI 均有实现。集群模式下调度由活动节点独占；未过期的登录 token 摘要共享并可在接管后继续使用，在线 SSH 会话无法跨节点切换。集群验收范围与限制见 [CLUSTER-HA.md](./CLUSTER-HA.md)。
