# SSH 命令过滤

> 中文 | [English](./COMMAND-FILTERS.en.md)

策略管理、终端命令审批和 SSH 作业审批分别支持 `command_filters.manage`、`reviews.command.manage`、`jobs.review` 委派；命令策略仍适用于全局连接角色。详见 [RBAC.md](./RBAC.md)。

本文描述当前命令过滤 ACL 的规则、匹配顺序和 PTY 解析边界。竞品 = JumpServer 企业版；本功能是按本项目路线逐步对齐的一部分。

## 规则配置

管理员在“系统设置 → 命令过滤”维护规则。每条规则包含名称、用户/用户组范围、资产/节点范围、SSH 账号、匹配方式、命令模式、允许/拒绝/复核动作、优先级和生效时间。

- 用户、用户组、资产、节点范围可以留空表示不限定；用户和用户组不能同时填写，资产和节点也不能同时填写。
- 节点规则作用于该节点及后代资产。账号 `*` 匹配资产当前配置的 SSH 账号；其它值按账号精确匹配。
- 匹配方式支持完整命令、包含文本和 Go RE2 正则表达式。模式最大 256 字节。
- 优先级范围为 0–9999，数值越小越先检查；同优先级按创建时间和 ID 稳定排序。首条匹配规则生效；没有命中时允许。
- 有效时间为左闭右开区间。未设置开始时间表示立即生效，未设置结束时间表示长期有效。
- `复核` 动作会暂停命令提交，管理员可在“系统设置 → 命令复核”队列批准或拒绝。批准会将回车提交给远端 PTY；拒绝会发送 Ctrl+C 清除待提交行。5 分钟内未处理时自动拒绝。
- 活动规则适用于其用户/组、资产/节点和账号范围。无法识别的终端输入在存在适用的活动规则时会安全拒绝，因为无法证明它不匹配规则。

REST 管理接口为 `GET /api/v1/command-filters`、`POST /api/v1/command-filters` 和 `DELETE /api/v1/command-filters/{filterID}`，仅管理员可用。规则保存在单机 `command-filters.json`；集群模式使用 PostgreSQL 共享状态文档。

## PTY 执行与审计

Web SSH 与 `jms ssh` 共用同一个服务端 SSH 网关。创建会话时，服务端根据已验证的用户身份、用户组、资产节点祖先和 SSH 账号构造规则范围。网关在检测到回车提交时检查输入；拒绝时在回车前注入 Ctrl+C 清除远端 PTY 中待执行的命令行，并通过 WebSocket 显示命中规则。复核时，命令行文本可显示在远端终端，但网关不会转发回车；待复核期间的后续输入会丢弃。批准后才提交回车，拒绝或超时会发送 Ctrl+C。命令申请和处理结果以不同加密审计事件保存，并通过复核 ID 关联；记录包含处理人，允许/批准结果不代表远端执行成功。

管理员队列接口为 `GET /api/v1/command-reviews`，处理接口为 `POST /api/v1/command-reviews/{reviewID}/approve` 和 `/deny`。接口仅管理员可用，只列出内存中的活动待复核请求。会话断开时请求取消；进程重启后不恢复待复核会话，命令审计读取时会把无活动会话对应的孤立待处理记录显示为已取消。

## 当前边界

当前正则匹配的是命令输入文本，不代表目录权限。精确目录、目录树与正则目录规则列入 [SSH 稳定版](./SSH-FIRST.md)优先范围，尚未完整实现。可信当前目录和规范化的真实路径需要远端 Agent/受控执行及账号权限配合；终端提示符、`PWD` 或推断 `cd` 历史不能单独作为安全依据。

过滤器工作在交互式 PTY 输入字节流上，只能识别常见 shell 提示符和输入行，不能解析 shell AST 或证明命令实际执行语义。自定义提示符、终端应用、嵌套 shell、复合命令、别名/函数、多行粘贴和非标准按键序列可能触发保守拒绝或无法完整识别。规则不限制绕过跳板机的直连 SSH；命令结果/退出码和完整 shell 语义尚未实现。
