# 单机整站加密备份与恢复

> 中文 | [English](./BACKUP.en.md)

原生 `jms backup` 导出、校验和恢复完整单机数据，无需外置数据库或额外备份程序。先停止服务，再执行创建或恢复；归档校验无需停止服务。本批已通过 Go/Testify、Linux race、真实 SSH、Docker 卷恢复和完整生产浏览器验证；自动更新器和 PostgreSQL 集群备份仍待完成。

## 快速使用

先以原有部署模式成功启动本版本一次，再正常停止服务。启动时会记录实际存储模式和已验证的 Vault key 指纹；旧版本不会遵守新互斥锁，必须先停止旧进程。保持部署使用的 `JMS_DATA_DIR`、`JMS_VAULT_KEY` 环境一致。终端交互会隐藏口令输入，创建时二次确认。

```sh
jms backup create --data-dir /srv/jumpserver233/data --file /srv/backups/jms233.jmsbackup
jms backup verify --file /srv/backups/jms233.jmsbackup
jms backup restore --data-dir /srv/jumpserver233/data --file /srv/backups/jms233.jmsbackup --replace
```

`--data-dir` 默认读取 `JMS_DATA_DIR`，否则与服务端一样使用用户配置目录下的 `JumpServer233`。归档必须位于数据目录之外，且父目录已存在。创建不覆盖已有文件。空目录导入无需 `--replace`；替换现有数据必须显式指定该参数。JSON 输出包含备份 ID、来源版本、时间、文件数、字节数与归档 SHA-256，不输出凭据或逐文件清单。

自动化通过 `--passphrase-file -` 从受保护的标准输入读取口令，也可使用权限为 0600 的本地文件；不要把口令写进命令参数、Git、日志或流水线参数。口令要求 12–1024 字节，并应独立保管。Windows 使用用户受控 ACL 保护口令文件、数据/维护目录及归档；Go 的 Unix 权限位不能验证 Windows ACL。丢失口令后无法解密归档。

## 数据覆盖与格式

导出 `JMS_DATA_DIR` 内的用户、组织、库存、凭据、策略、计划、审计、录像和其它普通数据文件，包括恢复所需的 `vault.key`。使用 `JMS_VAULT_KEY` 时，先核对它与服务成功加载数据时记录的指纹，再将相同密钥封装到加密备份；不修改源目录。恢复后可以使用归档中的本地 key，或继续配置相同的外部 key。密钥值不进入回执。

`.jms233-maintenance/` 中的锁、暂存数据和旧快照不重复导出；恢复回执也不导出。数据目录外的启动环境、反向代理证书、`runtime.json` 和应用程序需要按部署方案单独保管。不能将本工具用于仅含旧本地导入文件的 PostgreSQL 集群目录；存储模式标记或 `JMS_CLUSTER_MODE=true` 会拒绝此操作。旧部署须先以原集群模式运行本版本写入标记，不能通过取消集群环境冒充单机。

容器格式为 `JMS233BK1`：scrypt 派生密钥、AES-256-GCM 分块认证、gzip/tar 数据及加密的格式版本/逐文件 SHA-256 清单。序号、长度和格式头参与认证；结束帧与物理 EOF 防止截断、重排、重放和追加数据。内存按 1 MiB 块处理，当前上限为 64 GiB 逻辑数据、200000 条文件/目录记录和 64 MiB 清单。拒绝路径穿越、跨平台危险文件名、大小写冲突、符号/硬链接归档和特殊文件；源目录中的符号链接也拒绝。

## 恢复、幂等与中断处理

先在数据卷内的 0700 私有目录解密并校验全部内容，通过后才切换业务数据。文件以 0600 恢复，目录和原有可执行文件以 0700 恢复，不恢复原主机 UID/GID 或组/公共访问权限。Unix 同步文件及目录；Windows 同步文件，并依靠持久日志和同卷重命名恢复，不宣称断电下有相同的目录同步保证。

恢复不合并库存，不创建重复 ID。相同备份 ID 和清单的重复导入返回 `unchanged=true`，保留第一次导入后新增或修改的数据；相同 ID 配不同清单会拒绝。显式替换保留完整旧数据于返回的 `previous_data_dir`，位于维护目录下，校验业务后再按保留策略处理，不自动删除。

恢复的是本地快照，不会回滚远端机器。快照之后已轮换的远端密码/密钥必须重新核对；当前恢复不会自动停用快照中的计划，启动后仍按既有调度与待确定操作恢复规则处理。首次恢复应在受控维护窗口核对凭据和自动任务；归档完整性校验不代表外部机器的状态也已恢复。

恢复保留数据根目录和锁，按顶层条目移动，因此支持 `/data` 直接作为 Docker 持久化挂载点和只读容器根文件系统。日志存在时服务先恢复，再打开任何库存或认证存储；不确定或损坏的状态拒绝启动，避免初始化空数据。可在停机后显式操作：

```sh
jms backup recover --data-dir /srv/jumpserver233/data
jms backup recover --data-dir /srv/jumpserver233/data --rollback
```

第一条继续已校验的切换，第二条恢复旧数据并保留部分导入内容到私有 `failed-data` 目录。回滚本身也使用持久阶段，可在再次中断后重复执行。应用程序数据格式的跨版本迁移仍需目标版本的启动和真实业务验证；容器清单校验不能替代应用兼容性验收。
