# SSH 密钥安装与轮换

> 中文 | [English](./SSH-KEY-ROTATION.en.md)

管理员可为纳管账号安装新 Ed25519 密钥、轮换当前私钥，并显式启用每七天自动轮换。Web SSH、CLI、监控和 SFTP 在保管库提交后使用新凭据；私钥不返回客户端。产品后端保持单体 Go 服务，状态支持单机及 PostgreSQL 单活 HA。竞品的账号改密支持密码和 SSH 密钥，参见 [官方说明](https://docs.fit2cloud.com/jumpserver/v3/guide/admin/account/account_change_secret/)；完整企业版范围见 [PLAN](./PLAN.md)。

## 相同私钥的纳管副本

同一规范化主机地址、端口、固定主机密钥、SSH 用户名和私钥指纹的资产，统一更换候选钥并协调旧钥撤销，包含同组织副本及停用、归档组织中的副本。不同私钥仍保持独立授权生命周期。地址别名或不同端口不会自动合并。

流程先加密保存全局参与清单，再将候选钥以各组织的保管库 key 写入待处理记录。平台验证新钥并逐个提交保管库；只有全部提交后才移除旧公钥。失败时保留新旧授权及阶段日志，恢复沿用同一候选钥和操作 ID。参与副本的凭据编辑和删除被阻止，避免清理阶段漏掉副本。新建冲突副本也会被拒绝。密钥持有证明通过签名验证完成，不比较会包含随机数据的 PEM 序列化字节。

全局清单、阶段和成员修订号整体使用 AES-GCM 加密，保存在根目录 `shared-keys.json` 或 PostgreSQL `shared-keys` 文档。私钥始终在各组织的加密记录中。单机重启或单活接管会加载全部组织保管库，包括停用、归档组织；尚未创建全局清单的既有待处理操作也会在撤销旧钥前检查并接入共享副本。

统一提交意图落盘前可从已准备的任一副本取消，取消只移除本次候选钥并保留原钥及独立轮换设置。进入统一提交后只能继续，页面关闭取消入口。已验证完成的收尾决策可在接管后完成剩余本地记录，不再次改动远端。每个组织只记录自身资产事件，以同一操作 ID 关联。拥有凭据管理权限的页面显示“密钥协同轮换”，不会列出其他组织或返回私钥。

## 单个资产操作

- 密码资产的「更多 → 安装 SSH 密钥」生成新密钥并切换保管库认证方式。远端密码保持原值；该私钥凭据结束密码轮换，可另行启用密钥轮换。
- 私钥资产的「更多 → 轮换 SSH 密钥」替换当前公钥对应的普通授权条目，保留限制选项、其他密钥及注释。新密钥算法为 Ed25519。
- 编辑私钥资产可启用每七天轮换，周期按当前凭据最近变更时间计算。已到期的计划在下次调度执行。配置计划需要资产管理和凭据轮换权限，服务端校验，单纯资产管理角色不能更改计划。
- 待恢复操作可「继续 SSH 密钥操作」；提交前可取消，平台先验证原凭据，再移除本次候选钥。提交后继续清理旧钥。取消保留自动计划，失败/取消后自动任务退避一小时；可编辑关闭计划。

## 提交与恢复顺序

1. 读取并验证 SSH/SFTP 能力与标准授权文件，校验失败不创建待处理日志或远端锁。
2. 将新旧凭据和操作标识加密写入持久化日志，随后获取账号目录内的协作锁。
3. 捕获旧条目及其限制选项，加密保存计划，再添加带本次操作标记的新公钥。
4. 使用新密钥建立独立 SSH 连接，验证主机指纹与账号认证。
5. 原子提交新保管库凭据、修订号、旧凭据备份及待清理状态。
6. 撤销已捕获的旧钥普通条目，再验证新钥、释放锁并完成日志。

因此，旧钥撤销发生在新凭据持久化之后。重启或接管可以用日志中的新旧凭据继续同一操作；不会重新生成另一把候选钥。记录变化、远端编辑、网络错误及写入结果不确定时保留待恢复状态，不宣称完成。安装和清理均可幂等重试。

API `POST /api/v1/assets/{id}/ssh-key-rotation` 要求 `request_id` 和 `expected_revision`；修订号来自资产的 `credential_revision`。同一已完成请求返回现状，旧修订的新请求被拒绝。取消接口为同路径加 `/cancel`，要求当前 `operation_id`。取消也递增管理修订号，旧请求不能重新生效。操作、重试、取消与结果写入凭据审计，包含服务端身份及操作 ID。

## 主机条件与文件保护

需要 Linux/OpenSSH、SFTP 子系统以及 `posix-rename@openssh.com`、`fsync@openssh.com`。使用登录账号的规范化主目录及 `.ssh/authorized_keys`；主目录、`.ssh` 和授权文件必须由该账号拥有，禁止组/其他用户写入，拒绝符号链接。文件上限 1 MiB，条目上限 8192 字节，当前钥最多 64 个限制变体。

更新使用账号目录中的独占锁、0600 临时文件、文件同步、冲突复查、原子替换与目录同步。锁令牌先完整写入再安装；恢复只接受相同操作的锁，不能自动抢占未知锁。当前钥的 `from`、`command`、`restrict`、转发控制等选项按原值复制，清理仅移除捕获的旧条目。当前钥同时用作 CA 时拒绝轮换，CA 管理另行实现；其他钥的 CA 条目保留。

协作锁协调本平台的更新。其他工具直接编辑文件时需协调操作；已观察到的限制变化或候选条目变化会被拒绝，其他新增条目在合并中保留。自定义 `AuthorizedKeysFile`、`AuthorizedKeysCommand`、根账号所有的受管文件、SSH CA/证书、集中目录、硬件签名和多活分布式密钥调度仍待实现。既有 SSH 会话继续使用其已建立的连接，撤销作用于后续认证。

## 验证

Testify 覆盖限制保留、条目冲突、CA 拒绝、加密日志、幂等请求、修订冲突、取消和阶段恢复。真实 Linux OpenSSH 夹具覆盖安装、旧钥登录拒绝、新钥转发限制、SFTP 文件语义、提交后重启恢复和不安全权限/符号链接拒绝。双节点 HA 用例在共享数据库中准备待清理日志，接管后继续撤销旧钥并用恢复的凭据执行实际命令。

Playwright 通过真实 OpenSSH 与 SSH 网关完成安装、轮换、主机公钥文件核对、计划配置、CLI、Web SSH、中英显示和只读操作者拒绝。Docker 仅用于提供测试主机；容器端口绑定 IPv4 回环，公开合成账号不能用于生产。统一入口、端口及实机用例环境变量见 [TESTING](./TESTING.md)。生产主机与生产 HA 故障演练需另行验收。
