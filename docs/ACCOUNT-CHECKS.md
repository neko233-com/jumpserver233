# SSH 账号连接性检测

> 中文 | [English](./ACCOUNT-CHECKS.en.md)

在 `/console/rotation-plans` 为已保存的默认或具名 SSH 账号执行真实认证，支持密码、私钥和已固定指纹的多级网关。检测不打开目标会话、不运行命令，不改密码、密钥、凭据修订或改密时间。检测结果是当时所用凭据修订的历史观察，不代表实时在线状态。

## 使用与权限

手动点击“检测现有凭据”，查看逐账号状态、错误、认证耗时和凭据修订。每条账号记录分别验证自己的凭据、路由和访问策略；同一远端账号的别名也分别检测，避免一条成功记录掩盖其他记录的配置错误。固定密码计划仍检测当前 Vault 凭据，不使用计划中的候选密码或所配特权账号。

执行需 `accounts.rotation.check`、`accounts.rotation.view`、`assets.view_all` 和 `assets.probe`；不要求改密执行、固定密码或特权改密权限。管理计划另需 `accounts.rotation.manage`；查看、执行与重试仍受组织、本人/`manage_all` 范围和当前身份权限约束。检测纳入升级前排空门禁，执行前后重新核对账号、网关绑定、待恢复凭据和访问策略。

周期检测默认关闭。启用后设置 1–720 小时间隔，界面初始建议值为 24 小时；保存已启用的计划可能立即触发一次认证。检测与手动/单次/周期改密独立调度，共用每计划串行队列。检测不移动改密的 `next_run`；权限被撤销或保留容量不足只暂停检测，不关闭原改密周期。每次真实认证会进入主机登录日志，应按主机锁定策略选择间隔。

## API、CLI 与 SDK

```text
POST /api/v1/accounts/rotation-plans/{id}/checks
{"request_id":"check-owned-request-001"}

jms account rotation check PLAN_ID --request-id check-owned-request-001 --wait
```

API 返回 202；支持现有四种认证方式和 `X-JMS-ORG`。Go SDK 为 `Client.CheckRotationPlan(ctx, planID, requestID)`。输入仅含请求 ID，不接受目标凭据、命令或候选密码。公开运行的 `operation` 为 `check`；既有改密运行省略该字段。JSON、CSV、通知和 CLI 只返回元数据，不返回认证能力、密钥或密码。

相同操作人、计划和请求 ID 返回原运行，不再次认证；请求 ID 跨检测/改密复用冲突。重放仍检查当前权限。`--wait` 对未成功结果非零退出；读取已有运行使用 `jms account rotation show-run RUN_ID`。

已结束的失败、拒绝、配置变更、取消或中断项支持单项/批量显式重试，沿用[重试接口](./ROTATION-RETRIES.md)与当前计划修订。检测重试使用当前已保存凭据，允许修复凭据后重新检测；成功项排除，来源项只占用一次，结果保留父子关系。此行为不放宽改密重试的凭据版本保护。

## 中断、通知与数据

单账号认证超时为 8 秒，外层工作期限为 10 秒。认证已经开始而结果写入失败、进程重启或 HA 接管时，标记 `check_interrupted`，不自动再次认证。尚未领取的排队项可继续。显式重试才发起新的认证。

未成功的已结束检测通过 `account_checks` 来源进入所属操作人的 `security` 通知，健康结果静默。详情提供账号数量、状态和结果入口，不包含凭据；检测也不计入改密报表。通知投递、订阅与元数据权限沿用[通知中心](./NOTIFICATIONS.md)。

独立周期、运行、审计、重试关系随现有加密数据和备份导出/导入保留；不增加外部服务或数据库依赖。旧版本的严格读取器可能不认识新字段，降级需恢复与旧版本匹配的完整备份。该功能不证明交互式目录审计或完整企业版功能已完成。
