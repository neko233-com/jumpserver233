## 数据含义

每个 UTC 分钟保存最后一次探测，而非所有原始采样。60 秒区间展示分钟记录，较大的区间对这些记录计算统计量；这不是每秒监控或原始样本的精确加权平均。最多查询七天、每次 1440 个区间，步长为 60–3600 秒的整分钟。

在线与离线均记录。缺失指标、无数据和离线不填成零；网络首样、计数器回退或绑定变化时速率保持缺失，真实零速率仍为有效零。混合区间标明在线和离线分钟数，指标统计只包含有效在线分钟。探测失败仅记录稳定状态，不保存 SSH 输出或错误堆栈。

当前主机、账号名、节点及完整固定指纹网关路径形成绑定。改地址、节点、账号名或网关路径后只展示当前绑定的数据；展示名称变化及同一目标的密码轮换保留连续性。停用凭据不取消已授予的查看权限，查看历史不需要连接权限。

## 存储和生命周期

默认单机，在组织数据目录的 `monitor-history/` 下按资产摘要和 UTC 小时分段，每段最多 60 个分钟记录。所有记录和元数据通过组织 Vault key 的 AES-GCM 加密，并绑定分段名称；本地采用私有目录、0600 临时文件及原子替换。相同时间及内容重试不写入；相同时间的不同内容拒绝，较早到达的同分钟样本不覆盖较新样本。

热缓存最多八段，按需读取查询范围。每组织最多 100000 个小时段；容量耗尽时拒绝新段并报告 `history_capacity`，不会静默覆盖其它主机。写入失败保留原持久化和内存状态，暴露 `history_unavailable`；SSH 探测结果仍反映真实连接状态。

查询严格过滤七天前记录。采集轮次检查保留期，物理清理最多每小时执行一次，删除完整过期小时段；重复清理安全。删除资产后 API 不再返回其记录，底层段按保留期清理。组织停止时不在后台擦除，其运行时恢复后继续清理。该保留期不是停机期间的定时擦除承诺。

集群模式沿用 PostgreSQL 单活和组织文档作用域，小时段加密后写入共享文档；接管节点枚举当前组织的段并恢复查询，不依赖前一节点的热缓存。单机旧文件可经已有 `LoadOrImport` 迁入共享文档；过期清理同步移除可归属旧文件，避免重新导入。在线快照、网络计数器差分和活动连接仍由新节点重新采集。

## 权限和接口

`GET /api/v1/assets/{assetID}/monitor-history?from=RFC3339&to=RFC3339&step=60` 使用当前平台身份与 `X-JMS-ORG`。每次查询重新核验身份、组织、用户组、节点和 SSH 账号的 `view` 授权；全局查看、连接或文件权限沿用资产列表的可见性语义。未授权、已删除或非 SSH 主机返回 404。响应禁止缓存，不含凭据、端点、网关或内部绑定；段数量仅统计所请求资产。

重复参数、非法日期/步长、超范围和过多区间返回 400；存储/完整性失败返回 503，不以空数据冒充成功。单次查询有十秒处理预算及原存储调用超时，取消后停止后续分段读取。该能力只读，不签发 SSH 会话。

Go SDK：`Client.MonitorHistory(ctx, assetID, from, to, stepSeconds)`。

```sh
jms monitor history ASSET_ID
jms monitor history ASSET_ID --from 2026-10-18T00:00:00Z --to 2026-10-18T06:00:00Z --step 300
```

CLI 默认最近一小时并输出结构化 JSON；沿用平台 Bearer 或 AccessKey 身份和组织选择，操作者不接触远端 SSH 密码。完整目标及剩余企业功能仍见[计划](./PLAN.md)。
